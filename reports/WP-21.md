- Items the package says to "decide and document" and the decision taken:
  - **I/O vs bus:** MCP catalog and dispatch live in `omacell-bus` (sync). `rmcp` + tokio live in `omacell-cli` so GUI/TUI do not compile an async runtime. File tools call registered `file.open`/`file.save`/`file.export` (CLI composition root).
  - **Headless changeset list:** `omacell mcp` also binds the WP-07b IPC socket, so `omacell changeset list|apply|revert` talks to the same `Bus`.
  - **Origins:** grid writes use `Origin::ExternalAgent` and default to `propose`. `apply=true` / `changeset_apply` attempt apply as `ExternalAgent` and are denied by `MutationPolicy` with a CLI hint. File I/O, recalc, audit, and queries run as `Origin::User` (the user started `omacell mcp`).
  - **`recalc --wait`:** flag exists for the skill done-checklist; with no async AI cells yet it is a no-op extra after `calc.recalc`.
  - **Card stub:** summary JSON (`schema: 1`, `kind: "summary"`) until WP-22.
  - **`render`:** returns `{code: "mcp.render", message: "GUI not running"}` when headless.
  - **Hand-off argv:** `omarchy agent prompt <fixed-instruction-with-private-path>` from the workbook directory. User/workbook-derived prompt, path, selection, skill, and diagnostic context are written to a mode-0600 request under the Omacell state directory, keeping sensitive text out of `/proc/*/cmdline`. Off-Omarchy prints the same shell-safe fixed instruction and `{hidden: true}` under `--json`.
  - **Notifications:** `integrations.notifications = "off"` silences everything; `recovery_only` (default) and `all` send `changeset.proposed` from `ExternalAgent`. Prefer `omarchy-notification-send`; else freedesktop D-Bus. Never write Omarchy config.
  - **Palette/status:** `ai.agent` is registered (removed from `DEFERRED_COMMANDS`). Hidden from palette ranking and diagnose-offer status when `detect_default_agent()` is `None` or `[ai.agent] diagnose_offers = false`.

### 2026-09-04 MCP session-capability follow-up plan (written before coding)

- Relabeling MCP session tools as `Origin::Ipc` kept the wrong authority:
  `Ipc` is the trusted same-user socket, and WP-07a.2 says agents must retain
  an agent origin even when they use IPC. `workbook_save` and `export` still
  write caller-chosen paths; the integration test confirmed those writes.
- Keep MCP provenance as `Origin::ExternalAgent`. Add a separate MCP session
  allowlist (`file.open`, `calc.recalc`) instead of granting Ipc-level
  `allow_direct_mutate`. Deny `file.save` / `file.export` from MCP.
- Reject MCP `recalc` while a changeset is still `Proposed`. Recalc mutates
  live state and advances `live_generation`, so `range_write` → `recalc` →
  user apply currently fails with `changeset.base` and never sees the
  proposal. Tests: propose, recalc denied, apply still succeeds.
- Expose the existing user-authorized `Bus::discard_proposal` on CLI and IPC
  (`omacell changeset discard`, additive `changeset.discard` control op) so a
  headless MCP session is not stranded after a rejected proposal. MCP catalog
  names stay frozen; the open-guard hint points at the CLI.

## What was built

WP-21 makes Omacell operable from any coding agent: a frozen MCP tool/resource catalog, a shipped `SKILL.md`, `omacell mcp` / `omacell agent`, and Omarchy hand-off that stays hidden until a default agent exists.

Review fixes hardened that surface: `command_run` cannot bypass changeset review through non-eligible mutations; MCP frames and `range_read` responses are bounded; custom sockets are private, preserve non-socket files, and serve up to 32 clients; workbook replacement clears stale changesets; a sheet named `card` retains a distinct resource URI; and diagnostic bundles are private mode-0600 files. The GUI/TUI status hint now reads an incrementally maintained `#REF!` count instead of scanning the workbook every frame.

## Deviations from the spec or the package (with reasons)

- **`rmcp` + tokio live in `omacell-cli`**, not `omacell-bus`. Catalog/session stay in bus (WP “module mcp”) without making GUI/TUI compile tokio. Pre-approved `rmcp` 3.1 (schemars 1 compatible).
- **One current workbook** in an MCP session (`workbook_list` is 0–1 paths).
  MCP `workbook_open` now refuses to replace it while a proposal is still
  pending; a user-origin `file.open` on the bus may still clear the store.
- **MCP session tools keep `Origin::ExternalAgent`.** WP-07a.2 says agents
  retain an agent origin even when using IPC. A narrow allowlist
  (`file.open`, `calc.recalc`) is the only session mutate path; save/export
  remain user actions. Recalc is denied while a proposal is pending.
- **`recalc --wait`** was initially a no-op handoff. WP-22/23 and the final AI lifecycle integration now settle async AI cells through the retained request/cache path when explicitly authorized.
- **`render`** always reports `GUI not running` in this headless MCP process (no GUI raster in the MCP binary).
- **Circular-reference diagnose offer** in the status line is not computed without a live `RecalcEngine` on the UI snapshot; `#REF!` cascade (≥2 `#REF!` cells) is. `omacell agent diagnose` and GUI/TUI diagnose hand-offs build the full WP-19 bundle.
- **Omarchy hand-off context** is stored in a private mode-0600 request file. The single positional prompt accepted by `omarchy-agent-prompt` contains only a fixed instruction and that path; no unsupported flags or sensitive user/workbook text are passed in argv.

## RFC (only if a frozen contract changed)

MCP tool names, argument fields, and URI templates stay frozen. Tool
descriptions now state that save/export are user actions and that recalc is
denied while a proposal is pending. No frozen core origin variant is added.

Additive IPC control op `changeset.discard` (same envelope as apply/revert/get)
so a headless MCP session can be unstuck without applying. Old clients never
send it; old servers reject the unknown op.
