# Report — WP-29: Public-repository security hardening

## Plan (written before coding)

- Files/modules to change: wildcard search in `crates/fn`; CSV plans, records, clipboard, preview, and writer in `crates/io`; range resolution and changeset retention in `crates/bus`; CI workflow references; security work-package documentation.
- Interfaces to expose: `FormulaTextPolicy`; documented CSV preview/clipboard/export limits; documented changeset count/byte limits; a stable `changeset.limit` error code.
- Tests and corpora to write first: exponential wildcard regression; excessive preview/clipboard dimensions; formula-like export text; streaming writer failure; oversized command range; changeset count and serialized-size budgets.
- Decisions: keep file loading progressive; bound only materializing clipboard/preview helpers; encode exports per record so non-UTF-8 output stays streaming; reject formula-like text by default, with explicit `preserve` and `escape` policies; reject rather than evict retained changesets.
- Open questions at planning time: GitHub security settings cannot be reviewed or enforced atomically in this code PR, so their exact owner actions and acceptance checks are deferred to WP-30.

## What was built

- `SEARCH` wildcard translation now uses Rust's bounded, linear-time regex engine instead of recursive backtracking. Both pattern and haystack obey the 32,767-character Excel text limit, and regex compilation is capped at 4 MiB.
- CSV/TSV preview and clipboard parsing now reject excessive byte, row, cell, column, and field counts before unbounded materialization. The streaming field guard counts columns outside quoted fields.
- `export_write` emits a BOM once and streams records to the destination. UTF-16/Latin-1 conversion retains one record, not the full file. The convenience `export` buffer, record payload, and text fields have explicit ceilings.
- CSV value export rejects formula-like text by default. Callers may explicitly preserve it for trusted consumers or prefix an apostrophe for spreadsheet-facing output.
- Command ranges, effect vectors/summaries, changeset proposal count/size, and total retained changeset bytes are bounded. Apply rechecks the live inverse budget inside the workbook transaction before committing.
- Range summaries are constant-size instead of concatenating one string per cell.
- CI and nightly actions are pinned to verified full commit SHAs with read-only permissions. Dependabot now tracks Cargo and Actions updates.
- Public package metadata no longer publishes a personal email, and the historical bootstrap report no longer exposes a local home path.
- WP-30 records exact owner-only GitHub setting changes, based on settings read on 2026-08-28.

## Interfaces exposed (for dependents)

- Stable bus error code `changeset.limit`.
- `ChangesetStore::retained_bytes()` for diagnostics.

## Deviations from the spec or the package (with reasons)

- A command-bus range operation no longer accepts one full column; the cap is 100,000 materialized cells. Formula dependency ranges remain compact and are unaffected.
- `export_write` may leave a valid output prefix when the destination, encoding, formula-text policy, or a size check fails. Atomic file replacement belongs at the file-command layer.
- GitHub code scanning, SHA enforcement, enhanced secret scanning, review approvals, and bypass policy require repository-owner choices and are split into WP-30 rather than changed implicitly.

## RFC (only if a frozen contract changed)

- `ExportPlan` gains the serde-defaulted `formula_text` field. Existing JSON plans continue to deserialize. Rust callers using exhaustive struct literals must add the field or use `..ExportPlan::default()`. Exact round-trip callers must opt into `Preserve`; the secure default is `Reject`.
- `export_write` is now streaming and can leave a valid prefix on error. Callers that require atomic files should write a sibling temporary file and rename after success.
- Public materializing helpers and the command bus gain stable ceilings. Oversized callers must narrow/split their work; large CSV output should use `export_write`.
- These frozen-contract changes are security fixes requested for review; merge remains the human approval point.
