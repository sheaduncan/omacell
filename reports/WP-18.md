## What was built

- `crates/core/src/sort.rs`: stable multi-key row/column sorting by value, fill, font, resolved icon, or custom list; header auto-detection; case sensitivity; blanks last in both directions; strict key bounds; hidden rows/columns remain in place; relative formulas move with cells.
- `crates/core/src/filter.rs`: saved AutoFilter state, exact/text/numeric/date/color/top-N/average criteria, case-insensitive dropdown search through `filter_value_options`, filter-owned hidden-row tracking, imported-state restoration, toggle and clear.
- `crates/core/src/tables.rs` and `workbook.rs`: non-overlapping create/resize/convert, duplicate-header normalization, theme table-style name, totals functions, calculated-column fill, adjacent-entry expansion, exact changeset restore, and structured-reference updates on rename.
- `crates/core/src/validation.rs`: whole/decimal/list/date/time/text-length/custom rules, Unicode-scalar text length, relative formulas, inline/range dropdown resolution, bounded invalid-cell query, and registry-aware formula evaluation.
- `crates/core/src/condfmt.rs`: cell/formula/text/date/blank/error/duplicate/unique/top-bottom/average rules, 2/3-color scales, data bars with negative axis, 3–5 icon buckets, property-wise priority and stop-if-true, theme defaults, registry-aware formulas, and a bounded resolved-overlay cache.
- `crates/core/src/flashfill.rs`: deterministic first/last-word, prefix/suffix, surround, and constant patterns.
- `crates/bus/src/data.rs` and `restore.rs`: typed public commands, strict enum/operator validation, exact changeset inverses for table operations, and theme-role defaults for new scales/bars.
- `crates/io/src/xlsx/{read,data,write}.rs`: modeled AutoFilter/DV/CF/table parse/write, correct nested OOXML, active-filter `sheetPr@filterMode` plus hidden `_xlnm._FilterDatabase` metadata, full raw AutoFilter preservation, raw-extras preservation only while the loaded model is unchanged, and safe preservation of definitions rejected by the strict model.
- `crates/io/src/omc/{read,write}.rs`: modeled filter/DV/CF records so `.xlsx → .omc → .xlsx` retains both semantics and eligible raw extras.
- `tests/corpus/data-tools/*.tsv`: committed, executed corpora for all four acceptance surfaces.

The 2026-09 review follow-up makes value-list filters and duplicate/unique

## Deviations from the spec or the package (with reasons)

- Slicers remain Tier 1, as WP-18 explicitly requires.
- Notes/comments do not follow sorted cells. Formula cells do follow and use `RewriteOp::Copy { drow, dcol }`; this is documented in `docs/compat/known-differences.md`.
- Three-color scales use the observed minimum, 50th percentile, and maximum;
  icon sets use percentage-of-range buckets matching the generated OOXML.
  Imported non-default threshold types remain byte-preserved while unchanged
  but are not exposed for editing.
- New scale/bar colors remain theme-derived as required by WP-18 and the
  Omarchy theming contract. The review claim that those defaults differ from
  Excel is therefore an intentional product requirement, not a defect.
- Flash Fill intentionally supports a deterministic pattern subset rather than Excel's full inference engine.
- SpreadsheetML does not identify whether a hidden row was hidden manually or by AutoFilter. On import, a hidden row that fails the saved criteria is treated as filter-owned; a hidden row that passes remains manual.
- Raw unsupported/invalid CF, DV, and AutoFilter XML is preserved while its successfully loaded model remains unchanged. Omacell does not expose unmodeled fields for editing.

## RFC (frozen contracts changed — approved by merge)

### Requested changes

- Extend the frozen public `Sheet` model with AutoFilter, validation, and conditional-format collections. The filter-owned hidden-row set stays crate-private. `SheetEditState` retains its existing `Eq` contract and now serializes these additions for exact undo/changesets.
- Extend frozen `TableColumn` with optional `totals_fn` and `Table` with defaulted `style_name`. Existing serialized tables migrate through serde defaults; Rust struct literals must add the new fields or use constructors.
- Add the WP-18 core modules, types, and methods listed above. Existing method signatures and `Event` variants are unchanged.
- Add public WP-18 command schemas to the frozen command catalog. `range.sort.header` is nullable so omission means header detection; explicit `true`/`false` remains deterministic. No IPC envelope field or version changes.
- Extend public `WorksheetExtras` with `autofilter_xml` and add `.omc` data-tool model records. Existing `.omc` files remain readable; new readers reject malformed model JSON rather than silently losing definitions.

### Why

The WP-18 state must participate in the workbook, undo/changeset snapshots, public command surface, and file-preservation layer. Keeping it in side maps would make edits non-atomic, break exact revert, and make `.xlsx` definitions disappear after legitimate edits.

### Migration and compatibility

- Serialized core fields use empty/default values, so older data loads without migration code.
- Downstream Rust code using `Table`/`TableColumn`/`WorksheetExtras` struct literals must add the new fields; constructor-based callers are unchanged.
- Command consumers should regenerate `commands.json`; existing command payloads and the IPC v1 envelope are unchanged.
- Older Omacell builds will not understand the new `.omc` model-record kinds. `.xlsx` remains the cross-version interchange format.

### Alternatives considered

- Sidecar-only state was rejected because it cannot provide exact undo, changeset inversion, or modeled save-after-edit semantics.
- Always letting raw extras win was rejected because clearing or editing a definition would silently resurrect the imported XML.
- Always regenerating raw definitions was rejected because unsupported OOXML details would be lost.

### Approval

Human approval was established by merge of PR #36; the frozen additions above are the accepted contract.
