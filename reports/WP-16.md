## What was built

A native eframe/egui wgpu front-end over the same WP-14 session and WP-15a `TaskRunner` as the TUI. Bare `omacell [file]` is the composition root: one watched `ConfigStore`, registered file/theme/UI commands, SIGUSR1, in-process IPC, then `omacell_gui::run`. Native builds enable both Wayland and X11. The GUI starts on an empty workbook and submits the requested file through the task runner, so large-file I/O no longer blocks construction of the window or delays creation of the cancellation/progress path. The startup request is queued before IPC begins accepting commands.

The GUI never wraps `Bus` in a toolkit mutex. Paint reads `TaskRunnerHandle::snapshot()`; nav/sel/view/palette/panel go through `apply_local_command` while the writer is busy; `Esc` cancels the focused queued or running request. Task and config producers wake egui when they queue an event, including work initiated over IPC, so an idle window no longer waits for incidental input before showing a result.

The focused-IPC integration publishes eframe/winit native focus through the
retained `IpcHandle`; loss clears the marker and drop removes it. The TUI uses
the corresponding Crossterm focus-change protocol, so shell IPC defaults reach
the foreground workbook rather than whichever process started most recently.

The grid is virtualized from `Viewport` Fenwick geometry (frozen panes + the visible window) with device-pixel snapping and tessellation feathering off. It paints explicit file-authored fills, font colors/sizes, and per-edge borders with Excel-style strength precedence without retheming those colors. Chrome is sheet tabs, an expandable formula bar, status line, JSON-aware command palette, resizable docked panels, optional `[layout] menu_bar`, and a context menu. Compact width hides tabs and the menu bar. Mouse covers select/extend/add, header click, header-edge resize and double-click auto-fit, `Ctrl+scroll` zoom, and shift/horizontal scroll. The post-WP-17 integration connects copy/cut/paste, fill-handle series, atomic drag-move, and `Ctrl`-drag copy to their bus commands. Toolkit copy exports TSV while retaining the rich internal cell payload; toolkit paste imports bounded text tables through one `range.set` command.

The post-WP-18 integration consumes conditional-format overlays from the task
runner's dedicated reader worker. Frozen and scrolling panes are requested as
separate bounded rectangles; rapid viewport changes coalesce, and results are
accepted only for the exact `Arc<ReaderSnapshot>` being painted. Effective
fill/font styles, positive and negative-axis data bars, gradient bars, and 3–5
bucket icons are painted without rule parsing or formula evaluation in egui.
The TUI consumes the same cache with terminal color plus bounded bar/icon
glyphs.

Session restore reads `session.toml` (zoom, sheet, cursor, panel, recents). `eframe::App::save` writes it when eframe persistence is active, and `Drop` provides the native close fallback when it is not. Successful asynchronous open/save adopts the path and title; an opened workbook reapplies its sheet view and compatible restored session state. Tab clicks synchronize both the UI selection and the workbook's persisted active sheet. Printable in-cell input is consumed once rather than once as a key and again as committed text, and the grid no longer steals focus from the formula bar.

The file-lifecycle completion registers `file.new`, `file.close`, and
`file.saveas` at the composition root. New workbooks apply configured sheet
count/date/precision defaults, clear the old file sidecar and workbook-scoped
AI cache, and reuse the bus's `WorkbookOpened` boundary so changesets and repeat
state cannot cross workbooks. Save and save-as snapshot retained selection,
scroll, zoom, freeze, split, and show-formulas state through the existing atomic
save/backup path, preserve workbook-owned gridlines, and adopt a save-as
destination. GUI and TUI clear dirty state and reconcile
path/title/selection only after successful task completion; new, interactive
open, and close require a repeated command before discarding unsaved edits. Required-argument
key bindings now open the existing schema-driven JSON prompt, fixing both F12
save-as and Ctrl+O open instead of submitting an invalid empty payload.

Theme roles map onto egui `Visuals` and grid colors. Fonts load from `LoadedConfig.shell.ui_font_path` when the composition root asks; tests keep bundled egui fonts so snapshots are host-independent. Reload (watcher, `theme.reload`, direct `ConfigStore::reload`) rebuilds visuals without resetting the edit buffer. Malformed non-ASCII color values now fall back safely instead of panicking.

The 2026-09-03 shared-runner follow-up gives each GUI integration-test process
one test-only harness permit. `HarnessParts` retains the permit for the same
lifetime as its temporary configuration and GUI, so Rust's parallel test
threads queue expensive `egui_kittest` harnesses instead of contending for the
runner's limited CPU. Each integration test is a separate process and therefore
has its own lock. The existing five-second async liveness guards are unchanged.

The adapter-gating follow-up probes the same backend set and adapter selector
that `egui_kittest` will use before any pixel-rendering test creates a renderer.
Developer and generic CI hosts without a compatible wgpu adapter report a clean
skip. Fixed integrated-GPU gates remain strict through `OMACELL_FIXED_GPU=1` and
fail when that required adapter is absent. Non-rendering AccessKit and lifecycle
tests continue to run without a GPU.

The 2026-09-04 interaction-edge follow-up completes the GUI-specific review
queue. Toolkit paste reuses the retained rich clipboard only when its exported
TSV still matches the toolkit payload, preserving formulas and styles without
mistaking later external clipboard contents for an internal copy. External
tables retain the bounded `range.set` path, while paste during in-cell editing
is inserted into the edit buffer under the same byte limit. Go To and modal
command panels now accept ordinary and composed text, submit their commands,
and clear their shared input after success; `:wq` waits for a successful save
before requesting close. Shifted punctuation maps to the logical characters in
the classic keymap. Grid virtualization jumps across arbitrarily long hidden
row and column runs with `AxisGeometry`, clips text and icons to cell bounds,
and clamps scrolling to the worksheet and frozen-pane limits. Docked panel
widths now use the configured CSS-pixel value, and the synchronous desktop
animation preference probe is cached for the process.

## Deviations from the spec or the package (with reasons)

- **One window per process.** Spec lists multi-window (one workbook per window). This package matches TUI/CLI: `omacell [file]` starts one instance; WP-28 owns the explicit multi-window decision/implementation and walkthrough. `cli.usage` rejects two files in one process today.
- **No display → exit 1 (`gui.display`)**, not a stub 3. CI `assert_cmd` has no Wayland; fail-closed instead of hanging in eframe.
- **Resolved by WP-28:** the custom grid painter renders bounded frozen and
  scrolling quadrants for horizontal, vertical, and four-way split panes, with
  device-pixel dividers and hostile-geometry limits.
- **Resolved by WP-28:** visible workbook typefaces pass through a per-family
  cache with Office-compatible substitutions and ordered fallback definitions;
  the fixed-host profile remains a release measurement rather than an
  implementation handoff.
- **Resolved by WP-28:** status segments expose registered commands as clickable
  buttons while retaining the same keyboard/palette paths and AccessKit roles.
- **Header resize/auto-fit is connected to the workbook.** Drag and double-click update `UiSession` immediately for responsive paint, then submit `format.colwidth` / `format.rowheight` on release so the single writer, undo/changesets, dirty state, and file save retain the size. Both retained frontends refresh viewport geometry after every committed workbook mutation, so palette commands, hide/unhide, structural edits, and undo repaint the committed sizes too.
- **CJK IME composition UI and Orca speech** remain ADR-001 human checks. IME commit events are forwarded; `TextEdit` on the formula bar uses winit IME.
- **`epaint_default_fonts` OFL-1.1 + Ubuntu-font-1.0** are allowlisted in `deny.toml`. They are the egui bundled fallback required when `ui_font_path` is absent; not GPL-family.
- **`tempfile` 3** (dev/bench) matches WP-13/14/15 isolated HOME/theme installs.
- **`schemars` / `serde`** (gui dev-deps) register `theme.reload` in GUI tests without depending on `omacell-cli` (cycle).
- **GUI integration harnesses are serialized within each test binary.** Rust's
  default parallel test threads caused unrelated five-second async liveness
  guards to expire together on shared CI. This affects tests only; product
  task execution and every timeout remain unchanged.

  wall-clock smoke ignored) + 23 lifecycle + 2 reload + 1 snapshot; the
  performance test is nightly-only

- `cargo bench -p omacell-gui --bench scroll -- --quick` — `gui_scroll_1m_software` **9.27 ms** (8.99–9.34 ms) after real viewport jumps and a full wgpu render/readback on kittest's CPU-preferred adapter. This is below the 33 ms software target. The original 175.56 µs result was invalid because it repainted the same rows and never rendered them.
