## What was built

A native eframe/egui wgpu front-end over the same WP-14 session and WP-15a `TaskRunner` as the TUI. Bare `omacell [file]` is the composition root: one watched `ConfigStore`, registered file/theme/UI commands, SIGUSR1, in-process IPC, then `omacell_gui::run`. Native builds enable both Wayland and X11. The GUI starts on an empty workbook and submits the requested file through the task runner, so large-file I/O no longer blocks construction of the window or delays creation of the cancellation/progress path. The startup request is queued before IPC begins accepting commands.

The GUI never wraps `Bus` in a toolkit mutex. Paint reads `TaskRunnerHandle::snapshot()`; nav/sel/view/palette/panel go through `apply_local_command` while the writer is busy; `Esc` cancels the focused queued or running request. Task and config producers wake egui when they queue an event, including work initiated over IPC, so an idle window no longer waits for incidental input before showing a result.

The grid is virtualized from `Viewport` Fenwick geometry (frozen panes + the visible window) with device-pixel snapping and tessellation feathering off. It paints explicit file-authored fills, font colors/sizes, and per-edge borders with Excel-style strength precedence without retheming those colors. Chrome is sheet tabs, an expandable formula bar, status line, JSON-aware command palette, resizable docked panels, optional `[layout] menu_bar`, and a context menu. Compact width hides tabs and the menu bar. Mouse covers select/extend/add, header click, header-edge resize and double-click auto-fit, `Ctrl+scroll` zoom, and shift/horizontal scroll. Clipboard, fill, and drag-move gestures remain visible but report their WP-17 ownership until those commands exist; they no longer submit unknown commands or race cut/paste tasks.

Session restore reads `session.toml` (zoom, sheet, cursor, panel, recents). `eframe::App::save` writes it when eframe persistence is active, and `Drop` provides the native close fallback when it is not. Successful asynchronous open/save adopts the path and title; an opened workbook reapplies its sheet view and compatible restored session state. Tab clicks synchronize both the UI selection and the workbook's persisted active sheet. Printable in-cell input is consumed once rather than once as a key and again as committed text, and the grid no longer steals focus from the formula bar.

Theme roles map onto egui `Visuals` and grid colors. Fonts load from `LoadedConfig.shell.ui_font_path` when the composition root asks; tests keep bundled egui fonts so snapshots are host-independent. Reload (watcher, `theme.reload`, direct `ConfigStore::reload`) rebuilds visuals without resetting the edit buffer. Malformed non-ASCII color values now fall back safely instead of panicking.

## Deviations from the spec or the package (with reasons)

- **One window per process.** Spec lists multi-window (one workbook per window). This package matches TUI/CLI: `omacell [file]` starts one instance; extra egui viewports are a follow-up. `cli.usage` rejects two files in one process.
- **No display → exit 1 (`gui.display`)**, not a stub 3. CI `assert_cmd` has no Wayland; fail-closed instead of hanging in eframe.
- **Clipboard, fill, and drag-move mutations are deferred to WP-17.** The GUI exposes the gestures but reports the owner when the catalog does not contain `edit.copy`, `edit.paste`, or `edit.fillselection`; it does not submit unknown commands or compose an unsafe asynchronous cut/paste sequence. WP-17 must register the matching command contracts before enabling the mutations.
- **Conditional-format rendering is deferred to WP-18.** WP-18 owns the evaluated-style cache/API; the GUI must consume that result after it lands rather than duplicate conditional-format evaluation in the painter.
- **One viewport is painted.** `UiSession` retains frozen/split state, but the custom painter does not yet render multiple split panes. Complete and verify the split painter at the WP-28 GUI integration gate.
- **Per-cell typeface substitution and an explicit shaping cache are not implemented.** The resolved shell font, per-cell font size/color, and egui's own galley cache are used. WP-28 must profile and complete family/fallback fidelity on the fixed host before release.
- **Status segments are rendered but are not yet interactive.** WP-28 owns the final GUI completion/a11y pass and must bind configured clickable segments there.
- **Header resize/auto-fit write `UiSession` viewport geometry**, not sheet `ViewState`. Same split as WP-14/WP-15; persisting sizes into the file waits on save.
- **CJK IME composition UI and Orca speech** remain ADR-001 human checks. IME commit events are forwarded; `TextEdit` on the formula bar uses winit IME.
- **`epaint_default_fonts` OFL-1.1 + Ubuntu-font-1.0** are allowlisted in `deny.toml`. They are the egui bundled fallback required when `ui_font_path` is absent; not GPL-family.
- **`tempfile` 3** (dev/bench) matches WP-13/14/15 isolated HOME/theme installs.
- **`schemars` / `serde`** (gui dev-deps) register `theme.reload` in GUI tests without depending on `omacell-cli` (cycle).

## Measurements

Host: local Linux. Review artifacts and temporary files stayed under repository-local `review-scratch/`; no `/tmp` paths were used.

- `cargo test -p omacell-gui` — lib 5 + a11y 2 + lifecycle 4 + performance 1 + reload 2 + snapshots 1
- `cargo test -p omacell-cli --test subcommands` — 14 pass, including no-display `gui.display` and GUI usage rejects
- `cargo bench -p omacell-gui --bench scroll -- --quick` — `gui_scroll_1m_software` **9.27 ms** (8.99–9.34 ms) after real viewport jumps and a full wgpu render/readback on kittest's CPU-preferred adapter. This is below the 33 ms software target. The original 175.56 µs result was invalid because it repainted the same rows and never rendered them.
- `cargo test --release -p omacell-gui --test performance` — samples 24 positions from row 0 through row 1,048,544 after pipeline warm-up: **7.94 ms mean / 13.22 ms p95** step + software render. The gate is 36.3 ms mean (33 ms + 10%), with a two-budget p95 stall guard. The debug `just check` build uses a 72.6 ms mean regression guard because unoptimized wgpu plus synchronous screenshot readback is not a product frame measurement.
- Presentation-aware first frame measured **333.67 ms** in release and **381–427 ms** in debug on the local CPU-preferred kittest adapter. The release result is 11.2% over the 300 ms product target, so this target is not claimed as met. The always-on software-CI regression bound is 500 ms; WP-28 now explicitly owns the fixed integrated-GPU render/presentation gate and 10% baseline.
- Theme reload mid-edit gated at **< 100 ms** (`theme_reload_preserves_edit_and_is_fast`).
- `cargo deny check` — pass after OFL-1.1 / Ubuntu-font-1.0 allowlist

New crates.io deps: `eframe`/`egui`/`egui_kittest` 0.32 (pre-approved, wgpu + accesskit + default_fonts). Dev: `criterion`, `tempfile`, `schemars`, `serde` (justified above).
