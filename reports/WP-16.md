## What was built

A native eframe/egui wgpu front-end over the same WP-14 session and WP-15a `TaskRunner` as the TUI. Bare `omacell [file]` is the composition root: one watched `ConfigStore`, registered file/theme/UI commands, SIGUSR1, in-process IPC, then `omacell_gui::run`. The GUI never wraps `Bus` in a toolkit mutex. Paint reads `TaskRunnerHandle::snapshot()`; nav/sel/view/palette/panel go through `apply_local_command` while the writer is busy; `Esc` cancels the running task.

The grid is virtualized from `Viewport` Fenwick geometry (frozen panes + the visible window), painted in fill → gridline → text → spill outline → cursor/fill-handle order with device-pixel snapping and tessellation feathering off so integer-scale hairlines stay 1 px. Chrome is sheet tabs, formula bar, status line, command palette, docked panels, optional `[layout] menu_bar`, and a context menu. Compact width hides tabs and the menu bar. Mouse covers select/extend/add, header click, header-edge resize and double-click auto-fit, fill-handle drag, drag-move with Ctrl-copy, Ctrl+scroll zoom, and shift/horizontal scroll. Session restore reads `session.toml` (zoom, sheet, cursor, panel, recents); `eframe::App::save` writes it back.

Theme roles map onto egui `Visuals` and grid colors. Fonts load from `LoadedConfig.shell.ui_font_path` when the composition root asks; tests keep bundled egui fonts so snapshots are host-independent. Reload (watcher, `theme.reload`, direct `ConfigStore::reload`) rebuilds visuals without resetting the edit buffer.

## Deviations from the spec or the package (with reasons)

- **One window per process.** Spec lists multi-window (one workbook per window). This package matches TUI/CLI: `omacell [file]` starts one instance; extra egui viewports are a follow-up. `cli.usage` rejects two files in one process.
- **No display → exit 1 (`gui.display`)**, not a stub 3. CI `assert_cmd` has no Wayland; fail-closed instead of hanging in eframe.
- **Fill-handle drop queues `edit.fillselection`**, which is still a WP-17 deferred command. The handle is painted and the drag updates the selection.
- **Header resize/auto-fit write `UiSession` viewport geometry**, not sheet `ViewState`. Same split as WP-14/WP-15; persisting sizes into the file waits on save.
- **CJK IME composition UI and Orca speech** remain ADR-001 human checks. IME commit events are forwarded; `TextEdit` on the formula bar uses winit IME.
- **`epaint_default_fonts` OFL-1.1 + Ubuntu-font-1.0** are allowlisted in `deny.toml`. They are the egui bundled fallback required when `ui_font_path` is absent; not GPL-family.
- **`tempfile` 3** (dev/bench) matches WP-13/14/15 isolated HOME/theme installs.
- **`schemars` / `serde`** (gui dev-deps) register `theme.reload` in GUI tests without depending on `omacell-cli` (cycle).

## Measurements

Host: local Linux. Cargo artifacts under `$HOME/.cache/omacell/target` (tmpfs `/tmp` SIGBUS on this machine).

- `cargo test -p omacell-gui` — lib 3 + a11y 2 + reload 2 + snapshots 1
- `cargo test -p omacell-cli --test subcommands` — 14 pass, including no-display `gui.display` and GUI usage rejects
- `cargo bench -p omacell-gui --bench scroll -- --quick` — `gui_scroll_1m_software` **175.56 µs** (174.46–175.84 µs) on kittest wgpu (CPU adapter preferred). Gate is 33 ms CI software / 16 ms GPU. This is a software-raster number; the same wgpu path is used on a GPU.
- `cargo test -p omacell-gui --test a11y first_frame_is_under_startup_budget` — **~68 ms** debug kittest first frame including wgpu init. Spec §12.1 is 300 ms cold start on the CI reference; this is recorded, not gated at 300 ms, because debug+kittest includes adapter setup. CI-safe bound in the test is 5 s.
- Theme reload mid-edit gated at **< 100 ms** (`theme_reload_preserves_edit_and_is_fast`).
- `cargo deny check` — pass after OFL-1.1 / Ubuntu-font-1.0 allowlist

New crates.io deps: `eframe`/`egui`/`egui_kittest` 0.32 (pre-approved, wgpu + accesskit + default_fonts). Dev: `criterion`, `tempfile`, `schemars`, `serde` (justified above).
