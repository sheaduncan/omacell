## What was built

In-app AI foundations, with all proposed mutations constrained to the command catalog. `evaluate()` is non-blocking; `settle()` batches pending AI cells (default 50) and `block_on`s chats. Cache is content-addressed in `xl/omacell/aicache.json` plus `~/.cache/omacell/ai/{hash}.json`; entries are verified against the full argument hash and invalidated when the prompt-template version, provider, or model changes (pinned entries still require the same input).

Key files:

- `crates/ai/src/{runtime,functions,cache,plan,formula,complete,import_assist,audit_ai,agent,autopilot,prompts}.rs`
- `crates/cli/src/ai_cmd.rs` — `ai.refresh|pin|freeze|plan|formula.*|complete|import.assist|audit|describe|agent.turn`
- `crates/bus/src/preview.rs` and changeset session/runner methods — bounded dry-run previews plus revise/discard of proposed changesets
- `crates/ui/src/{review,agent_panel,formula_assist,import_review}.rs` — retained toolkit-neutral changeset, conversation, formula, and import-plan review models
- `crates/{tui,gui}` — review panels and cell markers, agent loop, formula workflows, cancellable inline ghost completion, and explicit CSV-plan acceptance
- `tests/evals/*.jsonl`, `crates/ai/tests/evals.rs`, and `crates/ai/tests/local_model_eval.rs` — committed-response CI scoring and a nightly loopback-model lane
- `default/ai/prompts/*.md` (versioned Markdown)

## Measurements

- Recorded offline evals: plan exact commands 200/200 and effect equivalence 200/200 after actual changeset execution; formula execution 40/40; import plan validation/match 24/24; audit precision 1.0 and recall 1.0 on 24 seeded fixtures
- Injection suite: 52/52 responses across 13 task families produced zero accepted commands, zero policy changes, and zero workbook changes
- Cache hit: second `settle` after ready cells issues 0 extra HTTP requests
- Batching: 100 `AI()` cells with `batch_size = 50` → 2 recorded requests
- Malformed/incomplete AI cell batches fail with `ai.payload` and are requeued; `AI.TABLE` spills a 2×2 result
- Privacy snapshots follow the actual routed provider slot, preventing a local-default/cloud-fast card leak
- Opening a new workbook replaces per-workbook cache/results/pending state
- File-open and retained Lua startup/`on_open` queue zero provider requests on
  cache misses; a later AI input edit queues exactly one request under `auto =
  true`. With `auto = false`, the prior value remains stale until `ai.refresh`.
- `refresh_on_full_recalc = false` leaves a warm AI cache untouched; applying
  the setting live and issuing an explicit full recalc re-queues the unpinned
  cell. `ai.refresh` now schedules recalculation instead of only deleting cache.
- Budget: `max_cells_per_recalc = 1` with two pending cells → `ai.budget` and `confirmation()`
- `AI.FILL` XLSX: calamine and an asserted headless LibreOffice CSV conversion read cached `"Ada"`; Omacell restores the original `AI.FILL` formula and exact provider/model/input-hash/prompt-hash/timestamp provenance
- Values export/freeze preserves exact cached types (including text beginning `=`), uses sparse iteration, and omits `aicache` from values-only xlsx output
- Generated review/apply/revert tests leave proposals non-mutating, apply only accepted commands as one undo unit, and restore the exact pre-plan workbook; generated autopilot targets never escape their selected range, unreviewed future commands fail closed, and consent resets across workbook/config changes
- Nightly `local-model-evals` runs the committed corpus against a loopback `qwen2.5:0.5b` model without making required CI depend on model quality
- Retained Lua integration settles a custom async worksheet function through the GUI/TUI task-runner path, applies privacy-filtered request and validated-response hooks, rejects local-to-cloud hook downgrades, queues second-wave recalculation on the single writer, discards in-flight responses from superseded extension generations, removes stale extensions on successful source, preserves them on failed source, and clears them under stricter policy
- CSV/TSV opens now return the sniffed plan plus a bounded retained preview in both frontends. `A` explicitly requests an import proposal using provider-specific privacy filtering; schema policy strips sample values, detector redaction runs before hooks/providers, stale or pre-applied results fail closed, and only Enter reopens the source with the reviewed plan.
- AI-function request lifecycle now honors live `[ai.functions] auto`,
  `keep_stale`, batching/rate limits, and `refresh_on_full_recalc`. Startup,
  file-open, retained Lua source, and `on_open` record async hashes without
  authorizing a request; changed inputs, `ai.refresh`, and opted-in explicit
  full recalculation are the only automatic-cell request paths. Settled cells
  return through a retained incremental second wave.
- Release software-render million-row scroll: mean 6.79 ms, p95 9.83 ms (36.3 ms mean budget)
- `just check` green (`CARGO_TARGET_DIR=$HOME/.cache/omacell/target`); `cargo deny check` green
- 2026-09-01 formula-assist picker follow-up: focused UI/TUI/GUI tests and the
  full `just check` gate passed.

## RFC (only if a frozen contract changed)

Additive default method `AsyncNodeProvider::runtime_result` on the WP-04 trait so AI text/arrays do not need workbook `StrId`s at evaluate time. Existing implementors (the mock) keep the default `None`. Not a WP-01 frozen type; no wire-format change.

The final AI-function lifecycle integration adds default no-op
`begin_explicit_full_recalc` / `end_explicit_full_recalc` hooks to that same
WP-04 trait. Existing providers remain source-compatible; the hooks distinguish
a user-requested full refresh from startup, file-open, and internal settlement
passes without adding a command or wire field. This is not a WP-01 frozen type
and does not change a wire format.

The pre-WP-28 Lua integration adds the default method
`DynamicFnBody::async_node() -> bool` (`false`) to the frozen WP-20 trait.
Existing implementations remain source-compatible, while trusted Lua AI
functions opt into the established `AsyncNodeProvider` graph path without
adding a field to the public `DynamicFn` struct. This additive frozen-contract
change was approved by merge.

Additive bus-only proposal-review models and methods provide dry-run previews and
replace/discard operations for still-proposed changesets. Frozen core changeset
types and command/IPC schemas are unchanged.

`xl/omacell/ai-formulas.json` is a new bounded (100,000 records / 16 MiB),
versioned Omacell custom part.
It preserves AI formulas privately while the standards-visible worksheet cell
contains the cached value for external readers. It is additive and does not
change an existing frozen format.

New public command ids (`ai.*`) are additive to the WP-07a catalog. The
final integration adds the closed-empty `ai.assist` UI workflow
schema.

The import-review integration additively extends two frozen WP-07a argument
schemas: `file.open` accepts optional `plan` JSON, and `ai.import.assist`
accepts optional `preview` JSON. Both old path/plan-only requests remain valid;
the catalog envelope remains schema version 1. The optional fields are needed
so explicit acceptance can run through the existing atomic open command and so
the model can see the bounded preview after the privacy policy strips or
redacts values. This frozen-contract change was approved by merge.
