## What was built

In-app AI foundations, with all proposed mutations constrained to the command catalog. `evaluate()` is non-blocking; `settle()` batches pending AI cells (default 50) and `block_on`s chats. Cache is content-addressed in `xl/omacell/aicache.json` plus `~/.cache/omacell/ai/{hash}.json`; entries are verified against the full argument hash and invalidated when the prompt-template version, provider, or model changes (pinned entries still require the same input).

Key files:

- `crates/ai/src/{runtime,functions,cache,plan,formula,complete,import_assist,audit_ai,agent,prompts}.rs`
- `crates/cli/src/ai_cmd.rs` — `ai.refresh|pin|freeze|plan|formula.*|complete|import.assist|audit|describe|agent.turn`
- `default/ai/prompts/*.md` (versioned Markdown)
- `.omc` `aicache` read/write; xlsx custom part round-trip
- User-profile Lua reserves `omacell.ai.task` / `omacell.ai.fn` / `on_ai_request` / `on_ai_response`; runtime dispatch is not implemented and embedded scripts do not receive these capabilities
- Status-line AI segment (`AI: off · omacell ai setup` when disabled)
- Palette `?request` submits `ai.plan` on Enter; `omacell ai plan <book> <prompt>` exposes the same query in the CLI

## Deviations from the spec or the package (with reasons)

- **The required offline eval corpus is not implemented.** The 200 cases exercise parser/to-calls validation against programmatically supplied JSON; they are not natural-language model recordings, do not test effect equivalence, and do not cover formula/import/audit quality metrics.
- **Lua AI extension hooks are reserved but not operational.** `DynamicFn` has no `async_node`; `omacell.ai.fn` returns `#N/A`, named task metadata stays in the Lua runtime, and request/response hooks are not invoked. Embedded workbook scripts cannot register any of them.
- **`ai.plan` / `ai.agent.turn` are queries, not changeset proposals.** They return a catalog-constrained command list, but argument schemas are validated only if a caller later proposes the commands; callers do not yet automatically call `changeset.propose`. `Origin::PalettePlan` / `InAppAgent` cannot apply changes themselves.
- **Import assist never writes the live plan.** It returns `{current, proposed, applied: false}`.
- **Agent-panel UI, formula-bar ghost text, and completion debounce/cancellation are not wired.** Palette `?`, `Ctrl+Shift+A` (`ai.plan`), and the `ai.assist` formula-workflow picker are wired.
- **Configured `refresh_on_full_recalc`, AI-function `auto`, and autopilot scope are not wired.** Autopilot remains off until an explicit per-session opt-in control exists.
- **Excel `COPILOT()` is not mapped to `AI()`** (open-question HUMAN).
- **`omacell-ai` depends on `omacell-io`** for `ImportPlan` (io does not depend on ai).

## Measurements

- 200/200 structured plan-parser cases matched their supplied commands (`two_hundred_plan_evals_match_commands`); this is not an NL model pass rate
- Injection suite: trust/script/file/network/config/ai.agent payloads rejected; agent tool calls must also belong to the changeset-eligible catalog
- Cache hit: second `settle` after ready cells issues 0 extra HTTP requests
- Batching: 100 `AI()` cells with `batch_size = 50` → 2 recorded requests
- Malformed/incomplete AI cell batches fail with `ai.payload` and are requeued; `AI.TABLE` spills a 2×2 result
- Privacy snapshots follow the actual routed provider slot, preventing a local-default/cloud-fast card leak
- Opening a new workbook replaces per-workbook cache/results/pending state
- Budget: `max_cells_per_recalc = 1` with two pending cells → `ai.budget` and `confirmation()`
- `AI.FILL` xlsx: calamine reads cached `"Ada"`; Omacell reopen keeps `aicache` custom part. The optional LibreOffice subprocess result is not currently asserted.
- Values export/freeze preserves exact cached types (including text beginning `=`), uses sparse iteration, and omits `aicache` from values-only xlsx output
- PalettePlan changeset apply/revert restored the pre-plan cell
