## What was built

In-app AI foundations, with all proposed mutations constrained to the command catalog. `evaluate()` is non-blocking; `settle()` batches pending AI cells (default 50) and `block_on`s chats. Cache is content-addressed in `xl/omacell/aicache.json` plus `~/.cache/omacell/ai/{hash}.json`; entries are verified against the full argument hash and invalidated when the prompt-template version, provider, or model changes (pinned entries still require the same input).

## Deviations from the spec or the package (with reasons)

- **Lua AI extension hooks are reserved but not operational.** `DynamicFn` has no `async_node`; `omacell.ai.fn` returns `#N/A`, named task metadata stays in the Lua runtime, and request/response hooks are not invoked. Embedded workbook scripts cannot register any of them.
- **Import assist never writes the live plan.** It returns `{current, proposed, applied: false}`.
- **Configured `refresh_on_full_recalc` and AI-function `auto` are not wired.** Inline completion does enforce `auto` only for a local provider. Autopilot is wired as an explicit per-session UI opt-in with scope and operation caps; review remains the default.
- **Excel `COPILOT()` is not mapped to `AI()`** (open-question HUMAN).
- **`omacell-ai` depends on `omacell-io`** for `ImportPlan` (io does not depend on ai).

## Measurements

- Recorded offline evals: plan exact commands 200/200 and effect equivalence 200/200 after actual changeset execution; formula execution 40/40; import plan validation/match 24/24; audit precision 1.0 and recall 1.0 on 24 seeded fixtures
- Injection suite: 52/52 responses across 13 task families produced zero accepted commands, zero policy changes, and zero workbook changes
- Cache hit: second `settle` after ready cells issues 0 extra HTTP requests
- Batching: 100 `AI()` cells with `batch_size = 50` → 2 recorded requests
- Malformed/incomplete AI cell batches fail with `ai.payload` and are requeued; `AI.TABLE` spills a 2×2 result
- Privacy snapshots follow the actual routed provider slot, preventing a local-default/cloud-fast card leak
- Opening a new workbook replaces per-workbook cache/results/pending state
- Budget: `max_cells_per_recalc = 1` with two pending cells → `ai.budget` and `confirmation()`
- `AI.FILL` XLSX: calamine and an asserted headless LibreOffice CSV conversion read cached `"Ada"`; Omacell restores the original `AI.FILL` formula and exact provider/model/input-hash/prompt-hash/timestamp provenance
- Values export/freeze preserves exact cached types (including text beginning `=`), uses sparse iteration, and omits `aicache` from values-only xlsx output
- Generated review/apply/revert tests leave proposals non-mutating, apply only accepted commands as one undo unit, and restore the exact pre-plan workbook; generated autopilot targets never escape their selected range, unreviewed future commands fail closed, and consent resets across workbook/config changes
- Nightly `local-model-evals` runs the committed corpus against a loopback `qwen2.5:0.5b` model without making required CI depend on model quality
- Release software-render million-row scroll: mean 6.79 ms, p95 9.83 ms (36.3 ms mean budget)

## RFC (only if a frozen contract changed)

Additive default method `AsyncNodeProvider::runtime_result` on the WP-04 trait so AI text/arrays do not need workbook `StrId`s at evaluate time. Existing implementors (the mock) keep the default `None`. Not a WP-01 frozen type; no wire-format change.

Additive bus-only proposal-review models and methods provide dry-run previews and
replace/discard operations for still-proposed changesets. Frozen core changeset
types and command/IPC schemas are unchanged.

`xl/omacell/ai-formulas.json` is a new bounded (100,000 records / 16 MiB),
versioned Omacell custom part.
It preserves AI formulas privately while the standards-visible worksheet cell
contains the cached value for external readers. It is additive and does not
change an existing frozen format.

New public command ids (`ai.*`) are additive to the WP-07a catalog. The
final integration adds the closed-empty `ai.assist` UI workflow
schema; existing command schemas are unchanged.
