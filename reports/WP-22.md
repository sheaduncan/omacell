## What was built

`crates/ai` talks to models through two wire protocols, builds a redactable workbook card, and is the only path that serializes workbook content for a model. Tests never open a socket: `ReplayTransport` matches a canonical JSON POST against `tests/fixtures/ai/*.json`. Production HTTP is `reqwest` + rustls, used only outside CI. `RecordingTransport` is an explicit human-only wrapper that writes private replay fixtures without authorization headers.

Review hardening added bounded HTTP/SSE/replay inputs, bounded secret commands, in-flight cancellation, deferred secret resolution, fragmented tool-call assembly for both protocols, correlated assistant/tool-result history, per-request output-token ceilings, current Anthropic `output_config.format`, private bounded audit files, and validation that rejects credentials in URLs, plaintext secret headers, or malformed provider tool calls. Invalid workbook privacy parts fail closed to `schema`; formula strings and every diagnostic-bundle path use the same redactor.

## Deviations from the spec or the package (with reasons)

- **MCP `card` arguments stay empty.** WP-21 froze the catalog. Summary is the MCP payload; `--level` is CLI-only.
- **Detected patterns are redacted on every payload**, and also listed as suggestions until `ai.redact` marks are accepted. Suggestion metadata carries the placeholder, not the original sensitive substring.
- **`omacell ai setup` enables AI only when a local server is found.** Presence of the Omarchy default agent does not flip `[ai] enabled` (agent path needs no provider). An empty detection pass does not write `enabled = false`, so a cloud setup is not disabled.
- **`bus` does not depend on `ai`.** The real card is a `CardHook` from the CLI composition root.
- **Recording is an explicit transport wrapper, not a default mode or background action.** It records bodies for fixture creation but never headers; output is mode `0600` in a mode `0700` directory.
- **Token estimate is `ceil(chars/4)`**, no tokenizer crate.
- **OpenAI-compatible output limits use the legacy `max_tokens` field except for `oN` model names, which use `max_completion_tokens`.** This preserves broad local-server compatibility while honoring the current OpenAI Chat Completions requirement for o-series models.

## RFC — frozen contract additions (approval required)

1. Extend WP-12's public `AiProvider` with additive `timeout` and `headers` fields. Serde defaults preserve existing TOML compatibility; Rust callers using exhaustive struct literals must initialize the new fields. Sensitive header names are rejected and secrets remain limited to `secret_env`/`secret_cmd`.
2. Add `omacell_conf::patch_ai_setup` and `merge_overlays`, the narrow helpers required to preserve comments and compose the per-workbook privacy overlay without reparsing configuration.
3. Add `CardHook` and `McpCtx.card` to the WP-21 bus integration surface so the CLI composition root can supply the real card without creating a `bus -> ai` dependency. MCP tool names, `CardArgs`, resource URI templates, and wire schemas are unchanged.
4. Freeze `docs/schemas/card.schema.json` with this package, including pagination metadata, formula fields, token-budget/truncation fields, and the existing four levels. This is the card schema's first freeze, not a mutation of an earlier frozen card contract.

Approval was granted by merge. The additions are backward-compatible on serialized configuration and MCP wire traffic; the source compatibility exceptions are exhaustive Rust struct literals for `AiProvider` and `McpCtx`.
