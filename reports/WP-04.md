- Items the package says to "decide and document" and the decision taken:
  - **Runtime vs frozen `Value`:** evaluation uses `RuntimeValue` (owned text/arrays, lambdas, range refs). Commit interned `Value` into slots. No RFC — WP-01 `Value` is unchanged.
  - **Uncalled `LAMBDA` in a cell:** `#CALC!` (Excel). Closures live only in `RuntimeValue`.
  - **Language constructs vs WP-05:** `LET`, `LAMBDA`, `ISOMITTED` are evaluated here. `MAP`/`REDUCE`/`SCAN`/`BYROW`/`BYCOL`/`MAKEARRAY` stay `#NAME?` until WP-05c. Unknown registry names → `#NAME?`.
  - **Omitted LAMBDA args:** ordinary parameters may receive an explicit omitted call slot (for example, `LAMBDA(x,y,...)(1,)`), which `ISOMITTED` observes. Bracketed names remain structured references rather than parameter declarations.
  - **Circular refs:** never panic/hang. Iterative off → cells in the SCC write `0`, `RecalcResult.circular` lists the set (sorted). Iterative on → bounded loop using workbook `Iteration`.
  - **Range buckets:** cell edges for single cells; sheet / whole-column / whole-row / 256×256 block buckets for ranges. Whole-column is one column-bucket edge.
  - **Parallelism:** rayon inside a topological generation; cells sorted by `(sheet_id, row, col)` before and at commit. 1-thread and 8-thread results bit-identical. Volatile RNG (when WP-05 registers `RAND`) must be per-cell, not thread-scheduled.

  - **`AutomaticExceptTables`:** Excel *data tables* (what-if), not ListObjects. No data tables yet (WP-24) → same as Automatic. Documented.
  - **Workbook writes:** additive `set_slot` / intern helpers so recalc can write cached values without dropping formulas. Undo disabled around result commit.
  - **Snapshot:** include `tables` so structured-ref eval can use a reader snapshot.

## What was built

Tree-walking evaluator with Excel F-3.5 coercion, dynamic-array operators, `LET`/`LAMBDA`/`ISOMITTED`, spill/`#SPILL!`, a range-bucket dependency graph, and a rayon recalc engine with deterministic commit order. Function library is a stub `FnRegistry` (`lookup` → `None` ⇒ `#NAME?`) so WP-05 can register implementations. Async AI nodes are a sync `AsyncNodeProvider` plus `MockAsyncProvider`. No package split.

Review hardening corrected exact cycle membership, post-cycle dependent recalculation, nested async dispatch and stale propagation, exact async argument hashing, dynamic-range invalidation, registry-driven volatility and array lifting, protection/style preservation, spill ghost lifecycle and same-pass visibility, malformed array formatting, unary-plus/empty-concat coercion, and omitted LAMBDA argument syntax. Regression tests cover each corrected path.

Dynamic-reference ordering hardening (2026-09-02) now promotes the value-read
targets of `INDIRECT` and `OFFSET` into graph precedents after evaluation and
settles the augmented graph in bounded topological waves. Resolved targets are
still tracked separately for conservative edit invalidation, so shape-only
uses such as `ROWS(INDIRECT("A1:A3"))` do not create false value cycles.
Dynamic-only cycles use the ordinary circular/iteration policy, static
precedents remain intact, and reverse range buckets are rebuilt once per edge
update batch.

Spill-ownership hardening (2026-09-02) makes a live foreign spill ghost block
a second dynamic array instead of being overwritten. Collision checks consult
the spill occupancy map, unknown spill metadata fails closed, and ghost cleanup
only clears cells still owned by that origin. Deterministic commit order now
preserves the first spill and reports the later origin as `#SPILL!` with the
crossing cell identified.

Coercion parity (2026-09-03) now distinguishes formula expressions from
reference-origin text at arithmetic operators. Literal numeric text accepts
the active locale's grouping, currency, decimal, percentage, sign, and
exponent syntax; empty and boolean words remain text. A cell or range that
contains text is never silently promoted by `+`, `-`, `*`, `/`, `^`, unary
sign, or percent, while a truly empty referenced cell still becomes zero.
Formula number-to-text conversion uses the existing 15-digit decimal model
with a wider General budget instead of the 11-character cell-display budget.
The bounded numeric-text parser now has a dedicated fuzz target.

Implicit-intersection parity (2026-09-03) now returns a range cell only when
the formula coordinate identifies a unique intersection. One-row and
one-column ranges require the formula column or row respectively; 2-D ranges
require both coordinates to fall inside the rectangle. A missing intersection
returns `#VALUE!` instead of silently selecting the range's first cell. Scalar
and array rules are unchanged.

CSE and LET result hardening (2026-09-03) applies singleton-dimension
expansion when a fixed legacy array formula is larger than its result: scalars
fill the target, row results repeat down, and column results repeat across.
Coordinates missing from a non-singleton dimension remain `#N/A`, and results
larger than the fixed target remain truncated. `LET` frames now retain error
values so the calculation expression can inspect them with `IFERROR`/`IFNA`;
ordinary use still propagates the original error.

Undo intern-lifetime hardening (2026-09-03) now preserves the intern-bearing
cell slots from evicted undo units, cleared redo stacks, and aborted
transactions until the owning workbook can balance their string, array,
formula, and style holds. Every workbook delta-recording path and undo/redo
stack transition drains that handoff immediately; ordinary numeric/default
slots add no cleanup traffic. Undo history remains oldest-first and retains the
same public API and memory budget behavior.

Range-query performance hardening (2026-09-03) makes regional storage
iteration visit only occupied blocks that intersect the requested rectangle,
then merges their cells into deterministic row-major order. Dependency cycle
and generation analysis now builds a transient block index for the formula set
and resolves range and 3-D precedents from intersecting populated blocks rather
than rescanning every formula candidate for every node. The indexes are private
and transient, so public APIs and steady-state workbook memory are unchanged.

## Deviations from the spec or the package (with reasons)

- **No real `.omc` files.** WP-11 owns the format. Fixtures are an omc-style text dialect (`tests/corpus/eval/README.md`).
- **`MAP`/`REDUCE`/…** are WP-05c. They `#NAME?` here. Corpus LET/LAMBDA coverage does not call them.
- **Test-only `SUM`/`IF`/`INDIRECT`/`NOW`/`AI`** live in `crates/core/tests/eval.rs`, not in production `FnRegistry::new()`.
- **`AutomaticExceptTables`** behaves like Automatic until WP-24 data tables exist.
- **Uncalled lambda** in a cell is `#CALC!` rather than a new `Value` variant (frozen union).
- **Circular cells** write `0` plus `RecalcResult.circular`; there is no `#CIRCULAR!` in frozen `ErrorKind`.
- **Structured `Table[[#This Row],[Col]]`:** WP-03 parses the pair as a column span; eval recovers the item + column. Parser change left to WP-03 if they want a dedicated AST.
- **Pre-WP-28 integration — multi-cell CSE ranges (completed 2026-09-01).**
  `ArrayFormula` retains the fixed anchor range; recalculation pads/truncates
  without spilling, frontends show `{=…}`, and XLSX/OMC preserve the range.
  Materialization is capped at 1,000,000 cells to bound hostile documents.
- **§12.1 incremental 100k < 50 ms:** a *typical* one-cell edit in a 100k-formula model is **8.4 ms**. A worst-case star (one edit dirties all 100k dependents) is **228 ms**. Reported honestly; the typical gate is met.
- **`WorkbookSnapshot` gained `tables`.** Additive, not a WP-01 freeze break.
- **Empty text in function coercion remains zero.** Arithmetic operators now
  use their own stricter text path, but `to_number("")` stays zero because
  existing Excel-compatible function behavior such as `DOLLAR("")` depends on
  it. The shared parser itself rejects empty input, keeping the distinction
  explicit instead of treating text as an empty cell.
