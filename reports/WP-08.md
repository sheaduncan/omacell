  - Ignored 1 GB progressive load + criterion parse throughput.
- Items the package says to "decide and document" and the decision taken:
  - **CSV never becomes a formula.** A leading `=` is stored as text. CSV open must not inject formulas (F-9.6).
  - **`changed`** is true iff Auto/forced conversion stores Number, Bool, or Date. Text/empty stays `changed = false`.
  - **`Text` and `KeepAsText`** both store raw text. Sniff sets `KeepAsText` on a column when any sample cell is a leading-zero / long-id / alphanumeric / ambiguous-date trap so the whole column stays text.
  - **Dates in Auto:** ISO `YYYY-MM-DD` (optional time), 4-digit year in the locale date order, or month-name + day + 4-digit year. Two-digit years and invalid-for-locale-order values stay text (no order swapping). `SEPT1`/`MAR1` without separators stay text.
  - **Forced `Number`/`Date`/`Boolean`:** still refuse >15-digit numbers (cannot be an exact IEEE value). Failed parses stay text, `changed = false`.
  - **Boolean:** only `TRUE`/`FALSE` (case-insensitive). `1`/`0` are numbers or text, never bools.
  - **Latin-1** is byte↔U+00xx, not windows-1252 (`encoding_rs` has no ISO-8859-1 encoding).
  - **ASCII delimiter/quote only** (`csv` crate is byte-oriented).
  - **Undo is disabled for the duration of `load_into`.** File load is not a cell-level undo unit (WP-13 may wrap open).
  - **Progress/cancel** via `LoadOptions` callback + `Arc<AtomicBool>`, not `Event`.
  - **UTF-8 load is a passthrough** after optional BOM skip so parse can hit ≥ 100 MB/s. UTF-16/Latin-1 go through a streaming decoder.
  - **Export values** use the cell number format when present, else General / TRUE|FALSE / interned text / error display. Formulas write interned source.
  - **1 GB nightly test** streams a synthetic repeating CSV (fits the Excel row cap: 1,048,576 rows × one 1 KiB field) and asserts progress + that RSS does not hold a second full copy of the file.
- Open questions at planning time:
  1. Should a forced Number column that cannot parse error the load, or keep text? Plan: keep text (`changed = false`) so a 1M-row file is not aborted by one bad cell.
  2. Clipboard HTML: first `<table>` only, no CSS/script, no network. Plan: yes.
  3. Default export line ending on Linux: LF. Plan: yes (`LineEnding::Lf`).

## What was built

`crates/io` CSV/TSV I/O: sniff encoding/delimiter/header/separators, serde `ImportPlan` with conservative Auto conversion, preview that marks every changed cell, streaming load into `Workbook` with progress and cancel, export with the matching controls, clipboard table parsers, and an A-4.4 assist hook that does not call a model.

Review hardening made previews bounded by the requested row count, verifies the actual BOM instead of trusting plan metadata, enforces the field-size cap during progressive loads, detects single-quoted fields and ungrouped decimal commas, rejects unsafe `Quoting::Never` exports, and makes delimiter scoring overflow-safe.

## Deviations from the spec or the package (with reasons)

- **Preview tests live in `csv_auto.rs`**, not a separate `csv_preview.rs` named in the plan. Same assertions.
- **UTF-16 encode uses `str::encode_utf16`**, not `encoding_rs` Encoder (WHATWG encoders are not the right tool for UTF-16 output). Decode still uses `encoding_rs`.
- **Latin-1 is byte↔U+00xx**, not windows-1252, matching the spec name.
- **Thousands is `None` unless sniff sees a grouped number.** Locale thousands are not assumed; otherwise `1.234,56` can be misread as en-US grouping.
- **Cancelled load returns `csv.cancelled`** after writing the rows already parsed (partial workbook). The error is the signal; `LoadResult` is not returned.
- **1 GB test is a streaming `Read`**, not a file on disk, so nightly does not need 1 GB of free disk. The byte count is still ~1.07 GB (`MAX_ROWS` × 1 KiB).
- **Row-major storage append fast path.** `SheetStore`'s private block tracks its last occupied bit so progressive file loads append without rescanning the occupancy bitmap for every cell. This changes no public core type or wire contract and is covered by the existing randomized storage oracle.
