## What was built

ODS read/write, JSON array-of-objects import/export with bounded dotted flattening and a dotted selector, Parquet/Arrow read, HTML/Markdown file import (reusing WP-08 clipboard parsers) plus export, and native legacy BIFF `.xls` import. `xlsx::peer_lock_blocks` refuses open when a Calc/foreign `.~lock.*#` is present; ODS/JSON/HTML/MD saves now use the same lock, backup, cancellation, fsync, and atomic-replace path as `.xlsx`.

Review hardening added package/entry/depth/shape/output limits, ODS zip duplicate and compression-ratio checks, exact Parquet integer handling, JSON collision rejection, and a fuzz target covering every WP-27 parser. An earlier follow-up replaced the LibreOffice conversion subprocess with Calamine's native BIFF reader. The 2026-09-02 security follow-up moved that parser into the shipped private `omacell-xls-worker` companion so malformed input cannot abort the GUI, TUI, CLI, or IPC host. The legacy `[integrations] libreoffice_fallback` key remains accepted for config compatibility but is ignored.

The host performs a bounded OLE header/DIFAT validation before launch, sends the workbook over stdin, and accepts only a bounded XLSX reply that passes Omacell's normal package reader. The worker inherits no environment, disables core dumps, and has 1 GiB address-space, 10-second CPU, and 15-second host wall-time limits. It is installed under Omacell's private library directory rather than on the public `PATH`; neither LibreOffice nor temporary conversion files are used.

The 2026-09-04 ODS hardening follow-up caps materializing repeated cells at
one million per sheet before multiplying row and column repeats, while still
accepting structural empty runs across the full ODS grid. Its formula adapter
now preserves semicolons inside strings and translates local, absolute,
cross-sheet, and quoted-sheet ODF A1 references. Cell text retains explicit
spaces, tabs, and line breaks; annotations become modeled notes whose creator
and body no longer pollute displayed cell text. ODS and HTML export now reject
XML 1.0-forbidden characters with the destination format's stable typed error
instead of producing malformed markup.

The 2026-09-04 JSON, Parquet, and table-format follow-up preserves integer
JSON lexemes outside the exact IEEE-754 range as decimal text, while exact
integers and finite fractional/exponent values remain numeric. The Markdown
reader now reverses the escaped pipe and backslash sequences emitted by the
writer. Parquet NaN and positive/negative infinity become stable text instead
of invalid in-memory numeric cells, and HTML/Markdown import retains the
shared parser's `csv.limit` code and remediation hint.

## Deviations from the spec or the package (with reasons)

- **Parquet is read-only** as the package specified.
- **ODS write is v1 basic:** modeled values, same-sheet A1 formulas, merges, names, and a small style subset. Cross-sheet formulas fail explicitly instead of emitting a corrupt formula. Number formats are read but not emitted; full LO styles/themes, page setup, and charts are not rewritten.
- **JSON `--jq` is a convert CLI flag**, not a `file.open` schema field (WP-07a freeze). `file.open` on `.json` uses the document root.
- **`.xls` is never written.** Native import creates an in-memory workbook; save-as must target a writable format.
- **Legacy `.xls` parsing now uses a bundled subprocess instead of the package's in-process implementation.** Calamine 0.36.1 can follow attacker-controlled CFB allocation structures and allocate dense ranges before Omacell can validate them; an allocator abort cannot be caught reliably inside the host on stable Rust. The isolated process preserves native import without restoring the removed LibreOffice dependency.
- **Calamine is a runtime dependency only of `omacell-xls-worker`.** It is dev-only in the host `omacell-io` crate and is never linked into the GUI, TUI, CLI, or IPC process. This narrow exception to the repository's dev-only preference is required to retain `.xls` support while containing parser failure in a separate address space.
- **Legacy `.xls` fidelity is intentionally narrower than `.xlsx`.** Values, supported formulas and cached results, merges, workbook names, sheet visibility, and the date epoch are imported. VBA, drawings, comments, row/column geometry, and most formatting are not exposed by the BIFF reader and are not preserved.
- **ODS number-format read is intentionally bounded to common constructs:** numeric decimals/grouping, percentage, currency symbol, date, and time components map to Excel format codes. Conditional style maps and exotic locale calendars are not mapped; dates become Excel serials with a date format.
- **JSON `--jq` is a dotted object selector, not the jq language.** The help and CLI guide use that exact term; `--jq` is rejected for non-JSON input and conflicts with CSV `--plan`.
- **Parquet logical/nested/binary types are not coerced.** The importer accepts a documented scalar allowlist and returns a format error for anything else; integers outside exact IEEE-754 range become decimal text.
