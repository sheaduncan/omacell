## What was built

ODS read/write, JSON array-of-objects import/export with bounded dotted flattening and a dotted selector, Parquet/Arrow read, HTML/Markdown file import (reusing WP-08 clipboard parsers) plus export, and a LibreOffice `.xls`→`.xlsx` bridge. `xlsx::peer_lock_blocks` refuses open when a Calc/foreign `.~lock.*#` is present; ODS/JSON/HTML/MD saves now use the same lock, backup, cancellation, fsync, and atomic-replace path as `.xlsx`.

Review hardening added package/entry/depth/shape/output limits, ODS zip duplicate and compression-ratio checks, exact Parquet integer handling, JSON collision rejection, private automatically cleaned LibreOffice temporary directories, and a fuzz target covering every WP-27 parser. `.xls` conversion now reads the effective `[integrations] libreoffice_fallback` setting instead of always enabling the subprocess bridge.

## Deviations from the spec or the package (with reasons)

- **Parquet is read-only** as the package specified.
- **ODS write is v1 basic:** modeled values, same-sheet A1 formulas, merges, names, and a small style subset. Cross-sheet formulas fail explicitly instead of emitting a corrupt formula. Number formats are read but not emitted; full LO styles/themes, page setup, and charts are not rewritten.
- **JSON `--jq` is a convert CLI flag**, not a `file.open` schema field (WP-07a freeze). `file.open` on `.json` uses the document root.
- **`.xls` is never written.** Bridge converts to xlsx and opens that.
- **ODS number-format read is intentionally bounded to common constructs:** numeric decimals/grouping, percentage, currency symbol, date, and time components map to Excel format codes. Conditional style maps and exotic locale calendars are not mapped; dates become Excel serials with a date format.
- **JSON `--jq` is a dotted object selector, not the jq language.** The help and CLI guide use that exact term; `--jq` is rejected for non-JSON input and conflicts with CSV `--plan`.
- **Parquet logical/nested/binary types are not coerced.** The importer accepts a documented scalar allowlist and returns a format error for anything else; integers outside exact IEEE-754 range become decimal text.

## Measurements

- ODS own-reader round-trip: number, text, formula (including the `LOG10` ambiguity), merge, quoted sheet name/defined name, bold (`ods_round_trips_values_formula_merge_name_and_bold`)
- ODS second-reader round-trip: generated ODS → LibreOffice → xlsx retains the formula (`ods_written_file_reopens_in_libreoffice_if_present`)
- ODS adversarial cases: invalid typed values, repeated cells, compression bomb, and save lock; common percentage number style maps to `0.0%`
- JSON: nested object/array flatten + `.items` selector; scalar rows, flattened-key collisions, and duplicate export headers rejected; corpus `tests/corpus/json/items.json`
- Parquet: UTF-8 + int64 columns, exact `u64::MAX` text preservation, and unsupported binary rejection generated in-test
- HTML/MD corpus files import; leading-zero text and Markdown escaping covered; Calc lock on `.ods` → `xlsx.lock`
- `.xls` bridge: LibreOffice present on this machine; xlsx→xls→open recovered `3.0`; disabled-policy test does not execute LibreOffice
- `fuzz/fuzz_targets/other_formats.rs` builds and exercises ODS, JSON, Parquet, HTML, and Markdown byte parsers
- `just check` green locally after the review fixes (format, clippy `-D warnings`, workspace tests, doctests, docs)
- `cargo deny check` green (`advisories ok, bans ok, licenses ok, sources ok`); duplicate-version and unused-license allowances remain warnings
