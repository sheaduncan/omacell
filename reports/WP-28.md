## What was built

WP-28 now has a complete distribution surface instead of release placeholders:

- `packaging/` contains source and binary PKGBUILDs, a post-install hook,
  desktop/MIME registrations, the complete hicolor icon set, and an unprivileged
  clean-Arch smoke harness. LibreOffice is not a runtime or package dependency;
  native read-only `.xls` support remains available.
- `setup omarchy` emits Quattro's Lua launch-table binding and links the shipped
  skill into the user locations for Claude, Codex, OpenCode, Pi/Oh My Pi,
  Gemini, Grok, Copilot, Crush, and the generic Agent Skills path without
  replacing an existing user path.
- `docs/book/`, `book.toml`, the CLI example generator, and the generation/drift
  scripts provide a buildable user manual whose CLI, configuration, and Lua
  references are derived from the shipped APIs. Parser limits, AI/privacy,
  Omarchy, and printing/font behavior are release documentation rather than
  tribal knowledge.
- Packaging, Omarchy stable/RC/edge, fixed-host performance, nightly fuzz and
  dependency checks, and tag-release workflows are defined under
  `.github/workflows/`. The release job is held behind the external public-name
  environment gate. The Omarchy VM workflow passes the source archive through
  the exact `PKGBUILD_SOURCE_*` inputs consumed by the source recipe.
- The GUI release pass adds explicit Fluent-backed user-facing strings,
  reduced-motion behavior, four-quadrant split-pane painting, per-family font
  caching, clickable status actions, and retained keyboard/AccessKit panels for
  printer selection. Freeze and split traversal is bounded even when hostile
  workbook geometry hides or spans most of an axis. Tests cover the grid,
  palette, panels, status actions, split panes, font cache, reduced motion, and
  a keyboard-only workflow.
- Printing now represents arbitrary repeated row and column title bands,
  round-trips Excel `_xlnm.Print_Titles`, repeats those bands in PDF pagination,
  selects a metric-compatible installed face for PDF embedding, and exposes a
  persistent last-printer chooser through the existing `file.print` command.
- Minimal chart editing is complete through `chart.move`, `chart.resize`,
  `chart.title`, and `chart.axistitle`. These palette-visible commands preserve
  stable ids, use the retained task runner, and participate in direct undo/redo
  and reviewable changesets; invalid sheet/grid/axis targets fail closed.
- `benchmarks/release-budgets.json`, its fresh-result collector and validator,
  `just perf-check`, `just docs-check`, `just i18n-check`, repository release
  lints, the changelog, and `scripts/rename.sh` make the release assumptions
  mechanically visible. The fixed-host workflow now produces its own
  commit/run-attributed result artifact from Criterion, UI, memory, and live
  provider measurements instead of assuming an undocumented host file, then
  retains the validated evidence as a 90-day workflow artifact.
- Pull-request CI compiles every fuzz target and applies advisory, ban, license,
  and source policy to the root, fuzz, and both spike workspaces. Nightly uses
  one dated toolchain, rejects an empty target list, builds before running, and
  waits for the loopback model service before pulling the evaluation model.
- Optional LibreOffice oracle tests now share a test-only capability probe that
  converts a repository-generated XLSX fixture in an isolated profile. An
  executable that merely answers `--version` no longer enables the tests;
  feature-specific conversions remain hard assertions after the probe succeeds.
  The Python formula cross-check applies the same real-conversion gate.

## Interfaces exposed (for dependents)

- `PrintTitleBand<T> { start, end }` and `PageSetup::{title_row_band,
  title_col_band}` are the canonical non-origin print-title representation.
  `PageSetup::{row_title_band,col_title_band}` also migrate legacy origin-count
  fields at read time.
- `file.print {path?, printer?}` keeps its frozen argument schema. Its query
  result additively reports `printers`, `last_printer`, `printed`,
  `font_embedded`, and `warning`; choosing a printer persists only its name in
  the application state directory.
- `/usr/share/omacell/{default,i18n}`, the desktop/MIME/icon paths, shell
  completions, `omacell(1)`, and `/usr/share/doc/omacell/manual` are the stable
  installed distribution layout. `PKGBUILD-bin` consumes architecture-specific
  release-tree `.tar.zst` bundles and wraps them as an Arch package.
- `scripts/collect-perf-results.py --log ... --criterion-root ... --commit ...
  --run-id ... --output ...` owns all 17 §12.1 result mappings and creates the
  fixed-host JSON artifact. `scripts/check-perf-baselines.py [results.json]`
  validates the exact 10 percent boundaries, attribution, freshness,
  completeness, uniqueness, measurement provenance, and direction.
- `scripts/extract-i18n.py --check`, `scripts/generate-docs.py --check`, and the
  Clap reference example are reusable drift gates for future UI/API changes.
- `chart.move {id?,to}`, `chart.resize {id?,range}`, `chart.title {id?,title}`,
  and `chart.axistitle {id?,axis,title}` are the 1.0 chart editing surface.
  Omitting `id` selects the first chart on the active sheet; an empty title
  clears it. All four are changeset-eligible but remain outside the explicit
  autopilot allowlist pending a separate scope audit.

## Deviations from the spec or the package (with reasons)

- The app retains the already-shipped one-workbook-per-process/window model.
  Sharing multiple native windows in one process is not needed for 1.0 and
  cannot be selected responsibly without the G4 live workflow/Wayland pass.
- Software kittest render/readback remains a regression smoke, not a claim
  about surface presentation latency. The workflow rejects non-integrated
  adapters and creates the complete product-measurement artifact only from
  commands run in the current workflow, on the checked-out commit.
- The current task API exposes a completed response rather than a callback at
  the first byte. The fixed-host completion measurement therefore records the
  whole small completion round trip as the first-token value. This
  is conservative: a whole response below 300 ms necessarily delivered its
  first token within that bound.
- Theme reload's edit-preservation regression remains in every workspace run,
  but its wall-clock budget is enforced only by the fixed-host Criterion lane.
  PR 88's otherwise-successful Arch package job measured 188.64 ms for the same
  debug test on a shared runner, demonstrating that the former 100 ms assertion
  was a runner-speed check rather than a stable product-performance gate.
- No fallback TTF is copied into the repository. Arch packages depend on
  redistributable Carlito and Liberation families; PDF export embeds the
  resolved face. Standard-14 Helvetica is retained only as a warning-bearing
  final fallback when fontconfig supplies no face.
- A full chart property inspector remains explicit post-1.0 scope. The 1.0
  move/resize/title surface is implemented without pretending to provide every
  DrawingML property editor.

## RFC (only if a frozen contract changed)

`PageSetup` is a frozen serialized core type. This package additively introduces
`title_row_band: Option<PrintTitleBand<u32>>` and
`title_col_band: Option<PrintTitleBand<u16>>` because Excel print titles may
start away from the print-area origin. Existing `title_rows`/`title_cols` counts
remain readable and are converted by the accessors, so old `.omc` data keeps
its behavior. New XLSX/PDF paths use explicit inclusive bands. Omitting the new
fields preserves the old serialized default, and no existing field changes
meaning.

The frozen `file.print` arguments are unchanged. The result gains only optional
status fields so older callers can ignore them. A second print command was
rejected because it would split one operation across two public schemas;
retaining only origin counts was rejected because it cannot represent Excel's
`$3:$4` or `$B:$C` titles. Merge of this PR records the required approval for
both additive contract changes.

The frozen command catalog additively gains `chart.move {id?,to}`,
`chart.resize {id?,range}`, `chart.title {id?,title}`, and
`chart.axistitle {id?,axis,title}`. Existing chart commands and schemas, event
variants, catalog version, IPC envelope, and serialized chart records do not
change. Each command is reviewable through changesets; automatic agent apply
remains denied by the independent autopilot allowlist. Merge of this PR records
approval of these additive command ids.
