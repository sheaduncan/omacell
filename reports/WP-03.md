- Items the package says to "decide and document" and the decision taken:

  - **Depth:** 64, matching Excel’s nested-function limit.

## What was built

`omacell_core::formula` parses Excel formulas into a spanned AST, prints a stable canonical form, rewrites references for copy/cut/insert/delete/rename, and extracts graph deps. Parser works on canonical locale only (`,` / `.`). Function names are any ident + `(` (WP-05 validates). Frozen WP-01 types are unchanged.

Review hardening applies the 64-level depth cap to array-prefix recursion, validates R1C1 base cells and rewrite bounds, rejects sheet-qualified move sources that the sheet-local API cannot represent, and preserves 3-D sheet spans in extracted dependencies.

The 2026-09-02 sheet-rename follow-up wires the existing formula rewrite into
`Workbook::rename_sheet`. A rename now updates ordinary and legacy array cell
formulas in the same atomic undo unit, the bus rebuild/recalc path observes the
new dependencies, and local renames leave external-workbook references intact.

The 2026-09-02 unary-precedence follow-up corrects the Pratt binding order to
reference operators, negation, percent, exponentiation, multiplication, and
the remaining arithmetic operators. `=-2^2` now evaluates as `4`, while
negative exponents and left-associative powers retain their existing behavior.

The 2026-09-02 structured-reference follow-up implements Excel's apostrophe
prefix escape consistently in bracket scanning, nested selector splitting,
column spans, and AST column decoding. Formula printing retains the exact raw
source spelling, while evaluation uses the decoded header and no longer strips
literal leading or trailing brackets from real column names.

The 2026-09-02 defined-name follow-up makes formula-name expansion path-local,
scope-aware, case-insensitive, and bounded in both dependency discovery and
evaluation. Direct and mutual cycles now terminate as `#NUM!`; acyclic
precedents discovered before a cycle remain in the graph; paths beyond the
shared 512-call ceiling fail closed. A named `LAMBDA` leaves name resolution
before application, so deliberate terminating recursion continues to work.

The 2026-09-02 external-reference rewrite follow-up treats an external-workbook
AST as an opaque boundary for local structural mutations. Whole-row/column
insert/delete, cell-band shifts, and same- or cross-sheet moves now update only
local references. Copy/fill deliberately retains full traversal so relative
external references still move with the copied formula. The public `Expr::map`
behavior is unchanged; the local-only traversal is crate-private.

The 2026-09-03 sheet-qualifier validation follow-up rejects qualifiers applied
to non-reference expressions instead of silently discarding a single-sheet
qualifier or wrapping a function call in a 3-D node. Unquoted 3-D parsing now
uses the same `attach_sheet` validation path as quoted and single-sheet forms;
valid qualified cells, ranges, names, and spill references are unchanged.

The 2026-09-03 dotted structured-column follow-up distinguishes nested
structured selectors from an unqualified external-workbook token. Dotted
headers now parse in Microsoft's required `[[Amt.USD]]` and
`[@[Amt.USD]]` forms, while the single-bracket shorthand and a bare
`[Book.xlsx]` remain invalid. Escaped literal brackets do not masquerade as
nested selector syntax.

## Deviations from the spec or the package (with reasons)

- **Resolved — unary minus vs `^`:** the original report incorrectly claimed
  that Excel's engine contradicted Microsoft's precedence table. The parser
  and corpus now follow the documented order (negation, percent, then
  exponentiation), so `=-2^2` is `4`; `=2^-2` remains valid. Evidence:
  [Microsoft Support — Calculation operators and precedence in Excel](https://support.microsoft.com/en-us/excel/calculation-operators-and-precedence-in-excel).
- **Function-arg commas vs union:** comma is an argument separator inside calls (`in_args`), not parsed as union. Union still works in parentheses: `SUM((A1,C3))`. This is Excel, not a Pratt-min-bp trick (union is *tighter* than `+`, so parsing args “above union” would drop arithmetic).
- **Canonical print upper-cases built-in call names.** Lexically bound `LET`
  variables and `LAMBDA` parameters instead adopt their exact definition-site
  spelling in both value and call positions; evaluation remains case-insensitive.
- **Sheet names `TRUE`/`FALSE`** are quoted by the formula printer even when WP-01 `quote_sheet_name` would not (so they do not re-lex as booleans).
- **R1C1 relatives that land off-grid** fail at parse (`formula.parse` / out-of-range), matching WP-01 rather than storing an unresolved offset.
- **Resolved — structured column escaping:** the earlier corpus incorrectly
  treated apostrophes as wrapping quotes. It now follows Microsoft's documented
  prefix escape for `[`, `]`, `#`, `'`, and `@`, including the published
  `['#OfItems]` example. See [Microsoft Support — Using structured references
  with Excel tables](https://support.microsoft.com/en-us/office/using-structured-references-with-excel-tables-f5ed2452-2337-4f71-bed3-c8ae6d2b276e).
- **Defined-name-only cycles use `#NUM!`:** the graph has formula-cell nodes,
  not name-definition nodes, so it does not invent a synthetic circular cell.
  Evaluation uses the existing recursion-limit error while dependency
  discovery stops the repeated name path. This preserves the frozen graph
  interface and follows the documented rule that direct or indirect
  self-dependency cannot be calculated. See [Microsoft Support — Remove or
  allow a circular reference](https://support.microsoft.com/en-us/excel/remove-or-allow-a-circular-reference-in-excel).
- Plan mentioned an `Arg` type; the public form is `Vec<Option<Expr>>`.
