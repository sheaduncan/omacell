## What was built

`omacell_core::formula` parses Excel formulas into a spanned AST, prints a stable canonical form, rewrites references for copy/cut/insert/delete/rename, and extracts graph deps. Parser works on canonical locale only (`,` / `.`). Function names are any ident + `(` (WP-05 validates). Frozen WP-01 types are unchanged.

Review hardening applies the 64-level depth cap to array-prefix recursion, validates R1C1 base cells and rewrite bounds, rejects sheet-qualified move sources that the sheet-local API cannot represent, and preserves 3-D sheet spans in extracted dependencies.

Key files:

- `crates/core/src/formula/{mod,error,ast,lexer,parser,printer,rewrite,deps}.rs`
- `crates/core/src/lib.rs` — `pub mod formula;` only (no other-mod reorder)
- Corpora: `tests/corpus/formulas/{valid,invalid,rewrite}.tsv`

## Deviations from the spec or the package (with reasons)

- **Unary minus vs `^`:** Microsoft’s published table lists unary `-` above `^`, which would make `-2^2` = 4. Excel’s engine evaluates `-2^2` as `-4`. The parser matches the engine (`^` tighter than unary minus). `%` is still postfix-tighter than `^` (`2^3%` = `2^(3%)`).
- **Function-arg commas vs union:** comma is an argument separator inside calls (`in_args`), not parsed as union. Union still works in parentheses: `SUM((A1,C3))`. This is Excel, not a Pratt-min-bp trick (union is *tighter* than `+`, so parsing args “above union” would drop arithmetic).
- **Canonical print upper-cases call names**, including `f(2)` after `LET`/`LAMBDA` (`F(2)`). Eval binds by case-insensitive name (WP-04).
- **Sheet names `TRUE`/`FALSE`** are quoted by the formula printer even when WP-01 `quote_sheet_name` would not (so they do not re-lex as booleans).
- **R1C1 relatives that land off-grid** fail at parse (`formula.parse` / out-of-range), matching WP-01 rather than storing an unresolved offset.
- Plan mentioned an `Arg` type; the public form is `Vec<Option<Expr>>`.
