# Report — WP-03: Formula lexer, parser, printer, and reference rewriting

## Plan (written before coding)

- Files/modules to create:
  - `crates/core/src/formula/mod.rs` — public API (`parse`, `parse_editor`, `print`, rewrite ops, `deps`), `ParseOptions` / `PrintOptions`, `RefStyle`, depth limit. `lib.rs` gains only `pub mod formula;` (no other-mod reorder).
  - `crates/core/src/formula/error.rs` — `ParseError { error: CoreError, offset, expected }`; codes `formula.parse` / `formula.length` / `formula.depth` constructed via `CoreError::new` (do **not** edit `error.rs` / WP-01 `codes::*`).
  - `crates/core/src/formula/ast.rs` — `Span`, `Expr`, `ExprKind` (literals, `Cell`/`Range`/`ThreeD`/`Name`/`Structured`/`External`/`Spill`/`ImplicitIntersect`, prefix/postfix, binary, `Call` with `Option<Expr>` args, array constants, paren). Distinct node kinds for named, structured, spill, and 3-D refs (F-3.2). `CellRef`/`RangeRef` reused with `sheet: None`; unresolved names live in `SheetSpec` on the node.
  - `crates/core/src/formula/lexer.rs` — tokens: numbers (`1e3`, `.5`, `5.`), strings (`""` escapes), bools, error literals, idents, quoted sheet names, 3-D prefixes, structured-ref spans, external `[Book.xlsx]`, operators, `{` `}` `;`, spill `#`, `@`, whitespace-as-intersection flag. `MAX_FORMULA_LEN` (8,192 bytes) rejected up front.
  - `crates/core/src/formula/parser.rs` — Pratt parser, Excel precedence (F-3.1): `:` > space > `,` > unary `-`/`+` > `%` > `^` > `*` `/` > `+` `-` > `&` > comparisons. `^` left-associative (Excel). Function args parsed above union so `,` is an argument separator; omitted args (`INDEX(A1:C9,,2)`). Any ident + `(` is a call (registry is WP-05). Editor mode returns a partial AST + first error offset + expected-token set. Depth cap 64 (Excel nested-function limit). Canonical locale only (`,` args, `.` decimal); do not touch `locale.rs`.
  - `crates/core/src/formula/printer.rs` — canonical A1 print (`=` prefix, compact spacing, upper-case functions / TRUE/FALSE / A1 letters, sheet quoting via `quote_sheet_name`). R1C1 print against a base cell.
  - `crates/core/src/formula/rewrite.rs` — copy/fill delta (relative axes move, absolute stay); cut/move (all refs into the moved range retarget, including absolute); insert/delete rows/cols (grow/shrink/shift; fully deleted → `#REF!`); sheet rename; table rename.
  - `crates/core/src/formula/deps.rs` — referenced ranges, names, tables; volatility (F-3.6: `NOW`, `TODAY`, `RAND`, `RANDBETWEEN`, `RANDARRAY`, `OFFSET`, `INDIRECT`, `INFO`, `CELL`); dynamic refs (`INDIRECT`, `OFFSET`).
  - Corpora: `tests/corpus/formulas/valid.tsv` (≥500), `invalid.tsv` (≥100 with error offset), `rewrite.tsv`. README names the package.
  - Tests: `crates/core/tests/formula.rs` (corpora + printer stability); `proptest` AST round-trip; criterion bench `parse_formula`; `cargo-fuzz` workspace `fuzz/` target `parse_formula`.
  - Deps: `criterion` (dev, pre-approved) in `workspace.dependencies`. No new runtime deps. `libfuzzer-sys` only inside the isolated `fuzz/` workspace.
- Interfaces to expose (types, commands, schemas, CLI):
  - `omacell_core::formula::{parse, parse_with, parse_editor, print, print_with, Formula, Expr, ExprKind, Span, ParseOptions, PrintOptions, RefStyle, ParseError, PartialParse, Arg}`.
  - Rewrite: `copy_delta`, `move_range`, `insert_rows`, `insert_cols`, `delete_rows`, `delete_cols`, `rename_sheet`, `rename_table`.
  - `collect_deps` → `Deps { ranges, names, tables, volatile, dynamic }`.
  - No commands, schemas, or CLI. Frozen WP-01 types unchanged (no RFC).
- Tests and corpora to write first:
  - `valid.tsv`: `input`, `print`, `mode` (`a1` default / `r1c1`), `note` citing Excel / F-3.1 / F-3.2.
  - `invalid.tsv`: `input`, `offset`, `code`, `note`.
  - `rewrite.tsv`: `op`, `src`, args, `expected`, `note` (fill-down/right, cut-paste, insert/delete, sheet/table rename).
  - Property: `print(parse(print(parse(x)))) == print(parse(x))` on the valid corpus and a `proptest` AST generator.
  - Fuzz target must not panic; short smoke 30–60s; throughput gate ≥ 100k formulas/s (criterion).
- Items the package says to "decide and document" and the decision taken:
  - **Leading `=`:** parse accepts with or without; canonical print always includes `=` (formula-bar form). `.xlsx` `f` text without `=` is WP-09’s to wrap.
  - **Canonical spacing:** compact: `=SUM(A1,B2)+1`, no spaces around binary ops except intersection (exactly one space). Numbers via `f64` Display (`=1e3` → `=1000`).
  - **Names vs functions:** ident + `(` is a call (any name; WP-05 validates). `TRUE`/`FALSE` are bools unless followed by `(`. Out-of-grid A1-shaped tokens (`XFE1`) are names, not `addr.ref` (that error is the address parser’s).
  - **Sheet ids:** formula AST stores `SheetSpec` names; `CellRef.sheet` stays `None` (WP-02 resolves).
  - **External refs:** parsed as `ExprKind::External` (`[Book.xlsx]Sheet1!A1`); F-1.5 follow-on-open is not this package.
  - **`LET`/`LAMBDA`:** ordinary `Call` nodes; evaluation is WP-04.
  - **Error codes:** new `formula.*` strings via `CoreError::new`; WP-01 `codes::*` untouched.
  - **Cut vs copy:** copy/fill moves relative axes only; cut/move retargets every ref (relative and absolute) whose referent lies fully inside the moved range. Partial range overlap is left unchanged (see Open questions).
  - **R1C1:** `ParseOptions { style: R1C1, base }`; relatives resolve with WP-01 rules.
  - **Depth:** 64, matching Excel’s nested-function limit.
- Open questions at planning time:
  1. Excel cut-paste of a range that only *partially* overlaps a formula’s referent (`=A1:C1` when cutting `A1:B1`) — split, `#REF!`, or leave? Plan: leave unchanged unless the whole referent is inside the cut.
  2. Does current Excel 365 treat `XFE1` as a name or as `#REF!` at parse time? Plan: name (eval → `#NAME?` if undefined).
  3. Should canonical print upper-case defined names? Plan: preserve name/table/column spelling; upper-case functions, bools, and A1 letters only.
