## What was built

Modeled OPC parts are regenerated from the workbook; unmodeled parts are copied byte-identical from `OpcPackage`. Worksheet XML injects `WorksheetExtras` fragments (autofilter, CF, DV, print, sparklines) in ECMA-ish order. Shared formulas are written as independent formulas (WP-09 already expanded them), while legacy fixed-range CSE anchors retain `<f t="array" ref="…">` and cached follower values. Formula `f` text is stored without a leading `=`. `calcChain` and `fullCalcOnLoad` are never written. Custom payloads go to `xl/omacell/` from `Workbook::custom_parts`.

The 2026-09-02 formula-dialect follow-up adds a private AST bridge for
Microsoft's [SpreadsheetML future-function
table](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/5d1b6d44-6fc1-4ecd-8fef-0b27406cc2bf).
On import it removes recognized `_xlfn.` / `_xlfn._xlws.` names and `_xlpm.`
lexical parameter spellings so Omacell evaluates its canonical function names;
on export it restores those reserved spellings. `_xlfn.SINGLE(expr)` maps to
the canonical `@expr` operator in both directions. The bridge covers ordinary,
shared, and fixed-array cells, defined names, validation and conditional-format
formulas, and pivot calculated fields. Unknown prefixed functions and
formula-like string literals remain unchanged.

The 2026-09-02 defined-name follow-up preserves the sheet identity of simple
cell, range, whole-row/column, and 3-D referents. Workbook XML keeps the raw
referent until all sheet names have been assigned, then resolves qualifiers to
stable `SheetId`s; missing sheet names remain formula text instead of being
silently converted to a relative range. The writer maps those ids through the
current workbook names, so later sheet renames also serialize correctly.
Unqualified ranges retain their existing relative semantics.

The 2026-09-02 worksheet-extension follow-up restores SpreadsheetML's required
container boundary. Preserved or modeled x14 conditional-formatting,
data-validation, and sparkline payloads are collected while their ordinary
worksheet siblings are emitted, then written under the final `extLst` using
Microsoft's registered worksheet extension URIs. Preserved `xr:uid`
attributes cause the revision and markup-compatibility namespaces plus
`mc:Ignorable="xr"` to be declared on the regenerated worksheet root. Standard
fragments remain in their schema positions, and duplicate singleton x14
validation or sparkline payloads fail the save instead of producing malformed
XML. The URI mapping follows Microsoft's [worksheet extension
table](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/07d607af-5618-4ca2-b683-6a78dc0d9627).

The 2026-09-04 XML and print-fidelity follow-up emits tab, newline, and
carriage-return characters as numeric references so XML attribute
normalization cannot collapse validation prompts, tooltips, or other modeled
text. SpreadsheetML page-break ids now translate to the model without the
former one-row/column shift, including the first valid boundary. Print-area
and print-title formulas share the core formula printer's quoting rule, so
numeric sheet names and A1-like names such as `Q1` remain unambiguous.

The 2026-09-04 protection/property follow-up distinguishes modern
`hashValue`/`workbookHashValue` verifiers from the legacy `password` forms.
When protection remains semantically unchanged, open/save re-emits the
validated source element so its algorithm, salt, spin count, and source-only
permission flags survive. An explicit protection edit remains authoritative
and uses the existing modeled legacy representation. The writer also merges
the modeled date system, tab color, and filter state with bounded source
`workbookPr`/`sheetPr` metadata, retaining VBA `codeName`, `outlinePr`, and
`pageSetUpPr` without changing frozen core serialization.

The 2026-09-04 relationship/drawing follow-up allocates generated worksheet
relationship ids against every source id and retains opaque relationship ids,
including printer settings referenced from preserved `pageSetup` XML. When a
modeled chart shares a source drawing with pictures or other non-chart anchors,
the writer replaces only chart-containing anchors and chart relationships; it
keeps the other bounded, validated DrawingML fragments and relationships.
Generated drawing, drawing-relationship, chart, and VML part names are allocated
case-insensitively against the whole package, and relative targets are computed
for both ordinary `xl/` parts and root-level custom parts.

The 2026-09-04 validation/conditional-format follow-up keeps x14 extension
rules and unsupported standard conditional-format types in their preserved XML
instead of inventing modeled A1 rules or downgrading them to `cellIs`. Standard
validation `sqref` lists expand into one equivalent modeled rule per valid
area, so regeneration retains every target. Modeled validation output now
emits `showErrorMessage` and `showInputMessage` according to the presence of
their respective title/message fields, making authored prompts and alerts
visible without changing the frozen validation model.

Atomic save uses a collision-resistant, exclusively-created temp file in the destination directory, `sync_all`s the file before backup rotation/rename, and `sync_all`s the parent directory afterward. All pre-rename error paths remove the temp file. Backup and unlock failures are reported rather than silently ignored. Numbered backups are `{name}.bak.{n}` (newest is 1).

LibreOffice-compatible `.~lock.{filename}#` files use its escaped, semicolon-terminated five-field format. Lock creation is exclusive; advisory locking plus inode revalidation prevents two writers from both recovering the same stale lock. Symlinks and unknown/foreign lock formats are refused conservatively, and Omacell only removes a lock that still belongs to the current host and process.

The writer now preserves rich strings (including distinct formatting for equal plain text), string formula caches, OOXML escaped control/literal tokens, defined-name constants and comments, row/column geometry, complete sheet views and protection, tab colors, hyperlinks, notes, tables, gradient fills, active-sheet visibility, macro-enabled package content types, and source worksheet relationships. New legacy notes receive a minimal VML drawing; existing VML is preserved. Table and package identifiers are unique, raw XML extras are validated as a single allowed fragment without embedded document declarations, and output limits and non-finite/model-range validation prevent malformed or unbounded packages. Threaded comments are reported by the diff and rejected explicitly until WP-17 can regenerate them, rather than being silently dropped.

`xlsx::diff` is a symmetric model-level L1/L2 JSON report. It compares exact cells/formulas, semantic styles and number formats, names, tables, workbook/sheet views, geometry, annotations, extras/custom payloads, and preserved L3 bytes plus content types in both directions. The `omacell diff` CLI is WP-13 over this API.

Key files:

- `crates/io/src/xlsx/{write,atomic,diff}.rs`
- `crates/io/src/xlsx/{mod,xml}.rs` — public save/diff API; XML escape
- `crates/io/src/error.rs` — `xlsx.write`, `xlsx.lock`
- `crates/core/src/geometry.rs` — additive `AxisGeometry::{iter_custom,iter_hidden}`
- Tests: `crates/io/tests/xlsx_roundtrip.rs`; unit tests in `atomic.rs`
- Bench: `crates/io/benches/xlsx_save.rs`

Key tests: `roundtrip_diff_empty_for_corpus`, `new_workbook_preserves_modeled_l1_l2_fields`, `diff_detects_symmetric_added_content`, macro/custom-namespace/XML-injection/numeric validation regressions, `saved_file_loads_in_calamine`, `saved_file_loads_in_openpyxl_if_present`, `saved_file_converts_in_libreoffice_if_present`, and atomic-save/lock race/cleanup/backup tests.

## Deviations from the spec or the package (with reasons)

- **`calcChain` is omitted** and never copied. A copied chain would be stale after regenerate; spec says never write `fullCalcOnLoad` unless the chain is absent — we write neither.
- **Shared formulas** are independent `<f>` cells, not `t="shared"`. Round-trip L1 matches because WP-09 expands them on load.
- **SST unused entries** from the original file are dropped (L1 is cell values).
- **New workbooks have no theme part.** Excel/calamine/LibreOffice accept this; a preserved package still copies an existing theme and keeps its workbook relationship.
- **At WP-10 time**, threaded comments/persons were a WP-17 handoff. They are now
  modeled and read/written with replies and resolved state. Legacy note VML is
  generated for new notes, while arbitrary source drawing shapes remain opaque
  L3 content rather than an unowned WP-17 deferral.
- **Autosave directory** `~/.local/state/omacell/autosave/` is F-9.7 app behavior (WP-13/UI). This package supplies the atomic write, lock, and `keep_backups` primitives.
- **`omacell diff` CLI** is WP-13. This package exposes the JSON-serializable API.
- **openpyxl** is not installed on this machine; the test skips only on `ImportError`/`ModuleNotFoundError` and would fail on a load error.
