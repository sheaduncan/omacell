  - **`format` and interned `Value::Text`:** WP says keep this free of workbook types beyond `Value`. `Value::Text(StrId)` cannot be rendered without WP-02 interners, so the public `format` takes `FormatValue` (number/bool/text/error/empty). A thin `FormatValue::from_value(Value)` maps what it can; dependents pass resolved text.
  - **Date system is not in the three-arg API.** F-1.6 stores 1900/1904 per workbook. `format(..., locale)` uses **1900**. `format_with` carries `DateSystem` for 1904 corpora and WP-05b.
  - **Built-in 0–49:** ECMA-376 18.8.30 for the language-neutral ids. 5–8 and 41–44 are Excel’s en-US currency/accounting forms, with the currency symbol taken from the locale table. 14 and 22 use the locale short-date order. 23–26 are reserved → `General`. 27–36 are CJK in ECMA; for non-CJK locales they still map to the ECMA Japanese/Chinese strings so `.xlsx` id round-trips, and a note column says so.
  - **General:** ECMA “11 characters including decimal, excluding sign”; scientific when `|n| ≥ 1e11` or `0 < |n| < 1e-4`; 15-significant-digit rounding first (F-2.6). `general_for_width` shortens, then scientific, then `#`s.
  - **Rounding:** Excel format rounding is half *away from zero*, not banker's (`f64::round`). Applied after the 15-digit display round.
  - **Serial 0 (1900):** Excel’s January 0, 1900 (`1/0/1900`), not OLE’s 1899-12-30.
  - **Section selection:** 1 section → all numbers (leading minus supplied for `n < 0`); 2 → pos+zero / neg (abs); 3 → pos / neg / zero; 4th is text. Conditions override; unmatched numeric → `##########` (Excel overflow). `-0.0` is not `< 0` so it uses the zero (3-section) or positive (1–2 section) part.
  - **Locale fallback:** unknown LCID → `en-US` separators/names (preserves WP-01 `separators()` behavior for codes we do not table).
  - **No `chrono` dependency** unless a civil helper actually needs it; serial math is small and must encode a date chrono cannot represent.

## What was built

`omacell-core` now formats Excel number-format codes and converts 1900/1904 date serials. Locale tables beyond `en-US` are data-driven. No workbook types beyond `Value` (via `FormatValue::from_value`).

Review hardening rejects unterminated delimiters, dangling layout markers, and fifth format sections; validates real civil calendar dates; and guarantees the magnitude returned by `general_for_width` never exceeds its configured width (the sign is excluded per Excel semantics). `DateSystem` lives in the shared `date_system` module and is re-exported from `dates`, so WP-02 workbook settings and the formatter use one type after the Phase 1 branches combine.

Key files:

- `crates/core/src/date_system.rs` + `dates.rs` — shared date-system identity, serial ↔ civil, Lotus 29 Feb 1900, 1904 epoch, weekday, time-of-day
- `crates/core/src/locale.rs` + `locale/tables.rs` — LCID tables; frozen `LocaleId` / `LocaleSeparators` / `EN_US` unchanged
- `crates/core/src/numfmt.rs` and `numfmt/{token,parse,render,general,number,fraction,builtin}.rs`
- `crates/core/src/error.rs` — `codes::NUMFMT_PARSE`
- `crates/core/src/lib.rs` — `pub mod dates;` and `pub mod numfmt;` (rustfmt inserts them in alphabetical order among existing mods)
- `docs/contracts.md` — new dates/numfmt sections
- Corpora: `tests/corpus/numfmt/*.tsv`
- Tests: `crates/core/tests/numfmt.rs`, `crates/core/tests/dates.rs`
- Fuzz: `fuzz/fuzz_targets/parse_numfmt.rs` (new `fuzz/` workspace; WP-03 `parse_formula` was not present)

## Deviations from the spec or the package (with reasons)

- **No `chrono`.** Civil math is Howard Hinnant algorithms so 29 Feb 1900 can exist. `chrono` remains allowed for later civil work.
- **`format` takes `FormatValue`, not interned `Value::Text`.** WP-02 interners are not here. `FormatValue::from_value` maps numbers/bools/errors/empty.
- **`format_with` for date system and width.** The three-arg API stays `format(value, fmt, locale)` as specified (1900).
- **`*` fill without `width` is a layout hint only** (no extra fill character). With `width`, it expands.
- **`[$-lcid]` / `[$€-407]` override date names, not number separators.** Separators follow the `locale` argument (workbook locale).
- **Era `g` emits empty; `e` is a four-digit year.** Japanese gengō / `[DBNum1]` / Hijri are not rendered.
- **Resolved 2026-08-31:** fixed-point formatting rounds the 15-significant-digit decimal coefficient, so `1.005` with `0.00` is `1.01`.
- **`numFmtId` 23–26 → `General`; 27–36 keep ECMA JPN strings** even for `en-US` so `.xlsx` ids round-trip.
- **lib.rs module order.** rustfmt inserts `dates` / `numfmt` alphabetically. Existing mods are not reordered relative to each other.
