- Items the package says to "decide and document" and the decision taken:
  - **`format` and interned `Value::Text`:** WP says keep this free of workbook types beyond `Value`. `Value::Text(StrId)` cannot be rendered without WP-02 interners, so the public `format` takes `FormatValue` (number/bool/text/error/empty). A thin `FormatValue::from_value(Value)` maps what it can; dependents pass resolved text.
  - **Date system is not in the three-arg API.** F-1.6 stores 1900/1904 per workbook. `format(..., locale)` uses **1900**. `format_with` carries `DateSystem` for 1904 corpora and WP-05b.
  - **Built-in 0–49:** ECMA-376 18.8.30 for the language-neutral ids. 5–8 and 41–44 are Excel’s en-US currency/accounting forms, with the currency symbol taken from the locale table. 14 and 22 use the locale short-date order. 23–26 are reserved → `General`. 27–36 are CJK in ECMA; for non-CJK locales they still map to the ECMA Japanese/Chinese strings so `.xlsx` id round-trips, and a note column says so.
  - **General:** ECMA “11 characters including decimal, excluding sign”; scientific when `|n| ≥ 1e11` or `0 < |n| < 1e-4`; 15-significant-digit rounding first (F-2.6). `general_for_width` shortens, then scientific, then `#`s.
  - **Rounding:** Excel format rounding is half *away from zero*, not banker's (`f64::round`). Applied after the 15-digit display round.
  - **Serial 0 (1900):** Excel’s January 0, 1900 (`1/0/1900`), not OLE’s 1899-12-30.
  - **Section selection:** 1 section → all numbers (leading minus supplied for `n < 0`); 2 → pos+zero / neg (abs); 3 → pos / neg / zero; 4th is text. Conditions override; unmatched numeric → `##########` (Excel overflow). `-0.0` is not `< 0` so it uses the zero (3-section) or positive (1–2 section) part.
  - **Locale fallback:** unknown LCID → `en-US` separators/names (preserves WP-01 `separators()` behavior for codes we do not table).
  - **No `chrono` dependency** unless a civil helper actually needs it; serial math is small and must encode a date chrono cannot represent.
- Open questions at planning time:
  1. Excel 365 `numFmtId` 14 display (`m/d/yyyy` vs `mm-dd-yy` vs locale short date) — ECMA and the UI disagree; plan follows locale short date and records ECMA’s `mm-dd-yy` in the builtin note.
  2. Japanese era (`g`/`gg`/`ggg`), `[DBNum1]`, Hijri/`B2` calendars — parse as locale/calendar modifiers, render as Western y/m/d until a later WP; flag if a corpus row needs them.
  3. Exact Excel fill (`*`) expansion without a column-width measure — return a layout hint and emit a single fill character unless `width` is set.
  4. NaN/Inf in-memory numbers have no Excel cell equivalent; plan to display `#NUM!`.
  5. Live Excel confirmation of `-0.0` with a three-section format (zero vs positive section).
