### 2026-09-02 theme-colour follow-up plan (written before coding)

- Add reader regressions first for SpreadsheetML theme indices 0–3 and for
  positive and negative tints on a non-grey colour. The expected behavior
  follows Microsoft's [`Color`](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.color?view=openxml-3.0.1)
  documentation: `theme` selects the corresponding colour-scheme entry and
  `tint` changes its HLS luminance in the range from fully dark to fully light.
- Parse colour-scheme entries by their semantic names instead of their XML
  child order, because SpreadsheetML's `lt1`, `dk1`, `lt2`, and `dk2` indices
  do not match DrawingML's required child order. Resolve valid tints through
  the documented HLS transform before interning file-authored styles.
- Keep the frozen `Color` and workbook contracts unchanged, retain the
  existing unresolved `Color::Theme` fallback when a theme slot is absent,
  add no dependency, and run the focused I/O suites plus the exact repository
  gate and strict documentation build.

## What was built

OPC zip reader with path/size/ratio limits enforced against actual decompressed bytes, a DTD-free depth-capped XML parser, and an `.xlsx`/`.xlsm` loader that fills `Workbook` at L1 (typed values and formula caches, formulas including shared-formula shift, custom number formats) and modeled L2 (styles, merges, freeze/split, names, hyperlinks, tables, comments/notes, row/col size+hidden, sheet visibility, workbook active view, byte-exact inline worksheet extras). Duplicate and absolute part names are rejected. Every OPC part is retained on `OpcPackage` for WP-10 L3. VBA is never executed. Unparsable formulas stay as text plus `xlsx.formula` warnings. The pre-WP-28 integration pass also models `<f t="array" ref="…">` as a fixed legacy CSE range rather than silently converting it to a dynamic spill.

Key files:

- `crates/io/src/xlsx/{mod,opc,xml,warnings,read}.rs`
- `crates/core/src/workbook.rs` — narrow rich-text, geometry, view, protection, and merge setters; no public raw mutable-sheet access
- `scripts/corpus-gen/xlsx/gen.py` and `tests/corpus/xlsx/*.xlsx` + JSON sidecars
- Tests: `crates/io/tests/{xlsx_corpus,xlsx_limits,xlsx_warnings}.rs`
- Bench: `crates/io/benches/xlsx_open.rs`
- Fuzz: `xlsx_zip`, `xlsx_sheet_xml`

Key tests: `every_corpus_xlsx_opens`, `l1_matches_calamine_for_all_corpus_cells`, sidecar L2 tests, zip-bomb / DTD / depth / `..` path tests, unparsable-formula warning.

The 2026-09-02 theme-colour follow-up maps DrawingML colour-scheme names to
SpreadsheetML's defined theme indices instead of relying on XML child order.
It applies valid tints with the documented HLS luminance transform and now
resolves theme colours consistently for cell fonts, fills, borders,
differential styles, rich-text runs, and sheet tabs. Missing theme slots retain
the existing semantic `Color::Theme` fallback.

The 2026-09-03 reader-edge follow-up sequences cells whose optional `r`
attribute is omitted, accepts Excel-authored `bgColor` differential fills,
falls back to General with an `xlsx.style` warning for malformed custom number
formats, ignores non-finite/non-positive font sizes, and clamps worksheet zoom
to SpreadsheetML's 10–400 percent range. Hyperlink ranges are modeled on each
covered cell and internal fragment markers are normalized; expansion is capped
at 100,000 cells per sheet, with an `xlsx.limit` warning instead of an
attacker-controlled allocation beyond that bound.

## Deviations from the spec or the package (with reasons)

- **At WP-09 time**, CF, validation, sparklines, charts, threaded comments, and
  persons were opaque handoffs. WP-17/18/25 now model the required L2 surfaces;
  unsupported drawing/VML content remains byte-preserved L3 data by design.
- **Phonetic runs (`rPh`)** are not modeled; the SST part is preserved.
- **Theme colours** resolve to ARGB, including HLS tint, when their named
  scheme slot is present; missing slots remain `Color::Theme` so the original
  index and tint can round-trip.
- **Column width** uses `chars * DEFAULT_COL_PX / 8.43`; **row height** `pt * 96/72`.
- **Corpus generator** uses stdlib `zipfile` so it runs without openpyxl. openpyxl remains the WP-named tool for later richer files.
- **Legacy CSE materialization** is limited to 1,000,000 cells so a hostile
  `ref` cannot force a worksheet-scale recalc loop.
- **Hyperlink range materialization** is limited to 100,000 cells per sheet.
  Larger ranges remain in the preserved source package and produce an explicit
  warning rather than expanding a compact XML attribute into an unbounded
  in-memory side table.
- **Resolved dependency advisory:** calamine is now 0.36.1 and shares `quick-xml 0.41` with runtime I/O. The former RUSTSEC-2026-0194/0195 ignores were removed from `deny.toml`; only the separately documented `ttf-parser` advisory remains ignored.

## RFC (only if a frozen contract changed)

WP-01 public types remain unchanged, but this package requires additive `Workbook` methods because `omacell-io` is a separate crate. The initial implementation exposed `Workbook::sheet_mut`, which also exposed `Sheet::store` and could bypass interner refcounts and undo invariants. Review remediation removes that method from the public surface and adds only bounded operations: `set_rich_text`, `set_row_height`, `set_col_hidden`, `set_col_width`, `set_sheet_view`, `set_sheet_protection`, and `set_sheet_merges`.

These are source- and wire-compatible additions; command schemas and IPC are unchanged. They preserve core ownership of the cell store and are used while undo is disabled during construction of a not-yet-published workbook. Merge constituted human approval of this additive frozen-contract change.
